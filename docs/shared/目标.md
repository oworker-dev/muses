# 最终目标

## 建成开放可演进的 AI 创作操作系统

让个人、团队与 Agent 在统一、沉浸式的创作空间中，把模糊意图可靠地转化为可编辑、可追溯、可复用、可组合、可协作并可发布的图像、视频、音频与音乐、品牌、演示和社媒资产；平台以完全开源、Build in Public 和开放能力契约连接模型、工具与工作流，使用户拥有成果、数据与选择，使新媒体、新模型和新场景无需重写核心运行时即可接入。

这是一个长期方向，不是某个版本的功能清单。阶段性路线必须能够解释它如何降低创作摩擦、增强可控委托或扩大能力复用。

## 背景与理由

项目来自创始人在 AI 短剧和 PPT 定制真实交付中对工具割裂、高成本、平台限制和不可编辑成果的不满。未来的创作系统不应只等待用户逐步点选工具，也不应把控制权完全交给不可观察的自动化。正确形态是人和 Agent 共享同一套结构化对象、命令、权限、执行记录与质量反馈：人负责意图、判断和最终责任，Agent 负责理解上下文、规划、探索与执行。

平台的长期壁垒不是接入模型数量，而是四种能力的共同成立：

1. Agent 能理解并安全操作真实创作对象。
2. 生成结果保持结构化、可编辑和可演进。
3. 一个意图能够形成跨媒体、跨渠道的完整交付。
4. 成功过程能够沉淀为品牌记忆、模板和工作流。
5. 用户能够审查、运行、迁移和继续使用系统与成果，不被平台锁定。

## 完成标准

长期目标只有在以下性质同时成立时才算实现；任一单项均不足以代表终局：

- **统一创作模型**：图像、视频、音频、音乐、文字、页面、演示和未来媒体共享稳定的资产、来源、版本与引用语义，同时允许各自拥有专用编辑模型。
- **人机同构操作**：人工、Agent、工作流和开放 API 对创作状态的修改通过同一命令与权限边界发生。
- **可靠执行**：长任务可以观察、取消、重试、恢复和审计，副作用幂等，失败不会破坏已确认成果。
- **真正可编辑**：平台保留图层、场景、时间、组件、字体、蒙版和生成来源等可用结构，而非仅保存扁平导出物。
- **跨入口复用**：核心能力至少能够被交互界面、Agent 和工作流三种入口调用，并产生语义一致的结果。
- **开放扩展**：模型、工具、插件和新媒体通过版本化契约接入；更换供应商无需改写项目或文档核心模型。
- **团队级治理**：租户隔离、权限、审批、来源、版权、安全策略、成本和审计覆盖完整创作生命周期。
- **规模与体验**：大型文档、并行生成、多人协作和跨设备恢复具备明确的性能与可用性指标。
- **商业闭环**：平台能支持从 Brief、探索、编辑、评审到批量适配、导出和发布的连续工作，并形成可持续的单位经济模型。
- **生态可持续**：第三方能够构建可发现、可授权、可观测和可版本化的能力与工作流，而无需进入平台内部实现。
- **开放且可迁移**：核心产品、协议和结构化格式公开可审查；用户能够自托管并导出项目、资产、版本、工作流和来源记录。
- **真实价值成立**：AI 短剧、PPT 定制及后续外部用户能在真实交付中持续获得可测量的速度、质量、控制、自由度和成本改善。

## 明确不做什么

- 不把“接入所有 AI 模型”当作产品目标；模型只是可替换能力实现。
- 不让某个垂直场景、供应商或 UI 形态定义核心领域模型。
- 不强迫图像画布、视频时间轴、演示分页和工作流图使用同一种编辑语义。
- 不在缺乏复用证据时提前建设庞大插件框架或拆分微服务。
- 不以完全无人监督的自主 Agent 取代用户责任；高影响操作必须受权限、预算和确认策略约束。
- 不牺牲可编辑性、来源追踪和数据隔离来换取短期生成演示效果。
- 不承诺在首个版本覆盖所有行业、媒体、发布渠道或企业治理需求。
- 不以代码保密、专有格式、数据扣留或故意削弱自托管版本作为主要商业壁垒。
- 不因为纳入 AI 音乐而承诺自研音乐基础模型或建设完整数字音频工作站。
- 不因 Build in Public 公开用户私有内容、凭证、个人数据、安全利用细节或无权公开的第三方材料。

## 当前进度摘要

项目已拥有可运行的 SaaS 基础设施与账户体系。当前先完成 Value Foundation，以真实 AI 短剧和 PPT 业务确认价值与体验基线；随后通过 Technical Discovery 验证会影响契约语义的技术路线，再进入 Wave 0 建立创作文档、命令、资产、任务与能力协议。当前事实状态以 `apcc status` 为准。
