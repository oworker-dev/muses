# 图片转可编辑技术方案

## 1. 文档状态

- 状态：`Approved / Provider Spike quality rework required`
- APCC 决策：`ai-3`，状态 `approved`
- 首个能力 ID：`image.to-editable.v1`
- 当前完成工作：确定性分层、真实 VLM/Image Edit 适配、Edit-only 流水线、层级场景图、Manifest、SVG、预览与 QA
- 当前未开始工作：独立 API/Worker 持久执行、数据库、SDK Client、Muses 宿主适配与 UI

本文件已经过产品负责人确认。当前交付证明确定性场景和 SVG 出口，但能力仍未加入
OpenAPI、Service Map、模型目录或生产服务发现。

### 1.1 首个交付证据

- 输入：`/root/a.png`，1672×941；
- SVG：`delivery/evidence/image-to-editable/corporate-report/editable.svg`；
- Manifest：`delivery/evidence/image-to-editable/corporate-report/scene-manifest.json`；
- QA：154 个原生文字、113 个矢量图形、3 个受限栅格层；
- 未嵌入完整原图，回渲染像素相似度 `0.9037`；
- 城市、波纹和品牌标记为独立栅格层，其余普通文字与图表为原生 SVG。

该证据是 fixture-driven 垂直切片，不能替代通用 Provider 证据。

### 1.2 Provider Spike v2 证据（失败回归样本）

- 输入：`/root/a.png`，1672×941；
- 输出：`delivery/evidence/image-to-editable/provider-spike-v2/`；
- 路由：`gpt-5.6-sol` 单次结构分析，`gpt-image-2` 单次前景层 Edit 和单次底图 Repair；
- 场景图：1 个复杂根底图、99 个原生 SVG 文字、24 个独立 raster 图层；
- 自动探测：24/24 raster 资产完成 Alpha/色键探测和裁切；
- 旧 QA：同尺寸、非空、三阶段回执齐全，回渲染相似度 `0.9073`，错误地标记为 `passed`；
- 供应商耗时：VLM `195289ms`、前景重绘 `30280ms`、底图修复 `31314ms`。

该结果不能作为质量证明。视觉检查发现全画布背景吞掉了应独立替换的清晰边界 artwork，
同深度全尺寸稀疏重绘造成跨元素串扰、比例漂移、截断、白色矩形和品红泄漏；旧 QA 没有
逐元素质量门。该目录保留它作为失败回归样本。

### 1.3 Provider Spike v3/v4 状态

- `provider-spike-v3`：新的层级场景图和局部批次已经运行，但 75 个 raster 元素均未通过
  模型资产门禁；`provider-spike-v3-source-fallback` 只用于验证保真兜底，像素相似度 `0.9986`
  但质量状态仍为 `partial`，不能视为可编辑通过。
- `provider-spike-v4-safe-batch`：复用同一 VLM checkpoint、按深度顺序并发重绘；已完成的
  8 个 Edit 请求被记录，随后图片渠道返回 `403 insufficient_user_quota`。该目录没有发布
  不完整 SVG，待额度恢复后可用同一命令重跑。

## 2. 决策摘要

图片转可编辑属于宿主无关的 AI 图像处理能力，而不是 Muses Web 路由、
DesignDocument 内部函数或供应商 SDK 包装。

推荐采用以下边界：

```text
Muses / another host
        |
        | media client + versioned HTTP contract
        v
Host-neutral Media API
        |
        | conversion id only
        v
Media Worker -> vision/image-edit adapters -> temporary artifacts
        |
        v
EditableSceneManifest + assets + SVG + QA + usage
        |
        v
Muses adapter -> Asset/Provenance -> DesignDocument Command
```

代码可以先处于 Muses Monorepo，但运行时和领域依赖保持独立。Muses 只能依赖
公共契约与 Client，不能导入服务端实现。API/Worker 是否以后迁出仓库，不改变
外部协议。

## 3. 目标与非目标

### 3.1 目标

1. 接收一张普通栅格图片，输出可被宿主重组和编辑的场景描述。
2. 普通文字以结构化文字元素输出。
3. 复杂非文字元素以独立透明或可去色键的图层输出。
4. 删除可编辑元素后生成视觉连续的干净底图。
5. 保留原图尺寸、元素顺序、逻辑位置、来源、模型和处理证据。
6. 输出通用 `EditableSceneManifest`、SVG、预览和 QA，不绑定 Muses 类型。
7. 支持异步查询、取消、显式重试、幂等提交和部分失败诊断。

### 3.2 非目标

1. 本阶段不先建设高清化、去背景、矢量化等独立产品能力。
2. 不承诺所有非文字元素内部都成为原生 SVG Path。
3. 不让媒体服务拥有 Muses Workspace、积分账本或 DesignDocument 权威状态。
4. 不为每个图像原子能力创建一个微服务。
5. 不把供应商型号、SDK 请求对象或密钥写入公共场景格式。
6. 不在技术方案获批前新增专业模式节点。

## 5. 权威状态与职责

### 5.1 Media Service 拥有

- `Conversion` 及其阶段、尝试、租约和取消状态；
- 不可变请求快照和幂等指纹；
- 模型调用记录、内部中间产物和 QA；
- 短期托管的输出，或向调用方预签名地址交付输出；
- 供应商执行 ID、实际用量和错误分类。

### 5.2 Muses 拥有

- 用户、Workspace、Project 和授权；
- 外层 Capability Job、积分预留、结算与退款；
- 长期 Asset、Artifact、Provenance 和访问策略；
- DesignDocument、Revision、Command 与 CreativeCanvas 放置；
- 面向用户的重试、接受、替换和发布决定。

Muses Job 可以引用远端 `conversionId`，但双方不共享数据库。远端完成通知只是
可重放提示，Muses 必须按 `conversionId` 查询并幂等接收结果。

## 6. 公共能力契约

公共契约不暴露 GPT 型号和 Muses ID。调用方提交质量意图，服务端根据部署配置
和版本化 Profile 选择模型，并在结果 Provenance 中记录实际路由。

```ts
type ImageToEditableRequestV1 = {
  schemaVersion: "1.0";
  source:
    | { kind: "upload"; uploadId: string; sha256?: string }
    | { kind: "signed-url"; url: string; sha256?: string };
  delivery:
    | { kind: "managed" }
    | { kind: "presigned-put"; targets: PresignedOutputTarget[] };
  options?: {
    quality?: "standard" | "high";
    preferredLanguages?: string[];
    transparentLayerPolicy?: "alpha-preferred" | "chroma-allowed";
  };
  callback?: {
    url: string;
    secretRef: string;
  };
  clientContext?: Record<string, string>;
};
```

`clientContext` 只能保存有长度限制的不透明关联值，不得承载授权、密钥、完整用户
对象或宿主领域状态。

### 6.1 HTTP 草案

```text
POST   /v1/conversions
GET    /v1/conversions/{conversionId}
GET    /v1/conversions/{conversionId}/result
POST   /v1/conversions/{conversionId}/cancel
POST   /v1/conversions/{conversionId}/retry
```

提交必须携带 `Idempotency-Key`。相同 Key 和相同请求指纹回放同一 Conversion；
相同 Key、不同请求返回稳定冲突错误。

### 6.2 状态机

```text
created -> queued -> running -> succeeded
                         |----> partial
                         |----> failed
                         `----> cancel_requested -> canceled

failed/partial -> queued       # 显式 retry，创建新 attempt
```

`partial` 只表示服务完成了可诊断输出但未达到默认质量门，不得静默当成成功。

## 7. 输出场景格式

SVG 是派生交付物，`EditableSceneManifest` 是跨宿主重建语义。Muses 接收后将其
转换为 DesignDocument；其他宿主可以转换为 PSD、PPTX 或自身图层模型。

```ts
type EditableSceneManifestV1 = {
  schemaVersion: "1.0";
  canvas: {
    width: number;
    height: number;
    colorSpace: "srgb";
  };
  background: AssetRef;
  elements: EditableElementV1[];
  exports: {
    svg: AssetRef;
    preview: AssetRef;
  };
  qa: ReconstructionQaV1;
  provenance: ConversionProvenanceV1;
  usage: ModelUsageV1[];
};

type EditableElementV1 = {
  id: string;
  type: "text" | "raster-layer" | "shape";
  sceneRole?: "background-field" | "bounded-artwork" | "container" | "leaf" | "native-text";
  zIndex: number;
  logicalBBox: BBox;
  generationBBox?: BBox;
  detectedBBox?: BBox;
  cropBBox?: BBox;
  placementTransform?: Matrix2D;
  opacity: number;
  rotationDegrees: number;
  asset?: AssetRef;
  text?: TextPropertiesV1;
  confidence: number;
  warnings?: string[];
};
```

坐标使用原图左上角为原点的像素坐标。BBOX 明确采用
`{ x, y, width, height }`，不混用 `x1/y1/x2/y2`。所有坐标字段必须声明它描述
逻辑布局、生成画布还是实际 Alpha 像素边界。

### 7.1 文字属性最低集合

- 原始文字与规范化文字；
- 字体候选、字重、字号、行高、字间距；
- 填充、描边、阴影和透明度；
- 对齐、换行、旋转、书写方向和语言；
- `logicalBBox`、基线信息和识别置信度。

找不到原字体时保留候选与警告，不伪造“精确字体已识别”。

## 8. 处理流水线

### 8.1 阶段总览

```text
ingest
-> analyze
-> prepare-edit-canvases
-> redraw-elements-by-depth
-> detect-and-crop-elements
-> repair-editable-background
-> assemble-scene
-> render-back-qa
-> publish-result
```

每个阶段写入持久检查点。模型调用完成后必须先保存响应与计费事实，再推进状态，
防止进程崩溃造成重复调用或费用丢失。

### 8.2 结构识别

VLM 输出文字、复杂非文字元素、BBOX、父子层级、图层顺序、编辑价值、分解策略、
保真风险和前景/底图角色。第一版允许全部非文字元素作为 `raster-layer`，但简单形状
的原生重建接口必须保留。

拆分以独立编辑价值和上下文共同判断：图表、卡片、线框、图标和视觉模块继续拆分；
复杂但有清晰轮廓、闭合边界、面板边、页脚曲线或可替换 footprint 的 artwork 使用
`bounded-artwork` 独立 raster 层，即使内部不适合转成 SVG。只有模糊渐变、环境光、融合
阴影、纹理和无法可靠分离的背景场才使用 `background-field`，由干净底图资产承接。
场景允许多个根前景元素，不能为补全树结构把它们强制挂到全画布背景。父层如果包含
可编辑子层，父层只拥有扣除全部后代后的 residual pixels。

识别结果经过 Schema 校验、坐标合法化、越界裁剪和稳定 ID 分配。无效元素进入
诊断，不允许直接驱动像素操作。

### 8.3 元素隔离输入

1. 在原图副本中先将文字区域本地替换为约定 chroma key。
2. 按非文字元素的生成区域裁切原始像素，并从父层裁切中扣除全部后代区域。
3. 按空间和语义上下文将非文字元素拆成小批，每批裁成局部 chroma key 画布，同时
   记录其全局 origin；关键 Logo、图表和 bounded artwork 默认单独处理。
4. 文字不进入生图；非文字元素按场景图深度和局部批次调用 Image Edit。
5. 每批输入只包含当前元素及其 residual 关系，不额外附带会造成串扰的原图上下文。
6. 模型输出回映射到全局坐标后，检测 Alpha bbox；局部坐标只决定裁切，不得改写版式。

批次执行按场景图深度顺序进行；同一深度内相互独立的批次默认最多并发 3 个 Edit 请求，
并发度可由运行时调低或调高（上限 8）。批次完成后按稳定索引归并回执和资产，失败时先
持久化已完成回执，避免把远端成功响应误判为模型无响应。

前景重绘输出尺寸变化时采用保持比例的色键留白，不使用 `fit: fill` 拉伸元素；若留白
导致元素无法在其生成区域内定位，批次必须失败并重试，而不是把偏移或变形写入 SVG。

### 8.4 非文字元素重绘

当前图像渠道不依赖 multipart Mask 或 Mask mode。模型根据元素清单和稀疏输入，以
普通 Image Edit 请求只重绘清单中的元素，删除裁切矩形自带背景，并保持
形状、颜色、尺寸和相对坐标。输出优先要求原尺寸 RGBA；不支持可靠 Alpha 时可以
输出约定 chroma key，但必须标记降级路径。色键是合成保留色，后处理会移除边界和
内部近色键孔洞并检测泄漏；不能把品红、白色矩形或噪声当成元素内容。

重绘不是传统抠图的后处理，而是模型内部完成语义选择、边界推断、像素重建和
Alpha/色键生成。Logo、二维码、精确图表和品牌元素必须有单独置信度与警告，避免
静默内容改变。

### 8.5 自动坐标探测与裁切

不得只按原始 BBOX 裁切生成结果。系统同时保留：

| 坐标 | 作用 |
| --- | --- |
| `logicalBBox` | 原图中的布局真值和最终放置目标 |
| `generationBBox` | 带安全边距的生成区域 |
| `detectedBBox` | 根据 Alpha/色键探测的实际输出像素范围 |
| `cropBBox` | 包含主体、阴影和安全边距的最终裁切范围 |

自动探测决定“裁哪里”，`logicalBBox` 决定“放哪里”。生成模型产生的轻微漂移不得
直接修改最终版式。检测结果与逻辑框宽高比偏差超过阈值、触及安全生成框边界或无法
检测时，元素必须进入失败/重试状态；禁止用非等比 placement 把变形合法化。

失败结果不得直接写入最终 SVG。若当前 attempt 的模型输出未通过逐元素门禁，流水线可以
生成一个明确标记为 `source-preserving-fallback` 的保真资产：它来自同一元素的原图稀疏
裁切，仅用于避免模型噪声、白底或截断污染最终预览，不被计为透明重绘成功。该资产保留
源图字形，覆盖区域内的原生 SVG 文字节点保持存在但以 `opacity="0"` 避免重影；Manifest
必须记录降级警告并保持 `partial`/`failed` 状态，不能用高像素相似度掩盖透明编辑能力缺失。

Alpha 路径至少区分主体 Mask 与效果 Mask：主体 Mask 用于对齐，低 Alpha 的阴影、
辉光和抗锯齿进入效果 Mask 和 `cropBBox`。一个元素可能包含多个断开的连通区域，
组件归属应受原 BBOX、中心距离和元素 ID 约束，不能把每个连通域都视为独立元素。

Chroma key 路径从画布边界做背景连通探测，再执行颜色距离、边缘 Alpha 估计和
去色边；合成保留色不属于源元素，因此内部闭合孔洞也必须透明化。对于真实可能使用
同色的素材，应切换原生 Alpha 或把该元素标为不可接受的色键降级。

### 8.6 干净底图

将文字和所有前景非文字元素区域在原图副本中本地替换为 chroma repair slots，再作为
普通 Image Edit 输入补全；不上传 Mask。只有 `background-field` 不进入删除区域；
`bounded-artwork`、图表、卡片、Logo 和局部框架都必须被移除后再修复。修复输出既是
干净底图，也是可移动、替换和再次编辑的根 raster asset。阴影归属必须明确：随元素
移动的阴影进入元素层；环境光、渐变、复杂颜色或融合背景结构留在底图。

### 8.7 组装

按以下顺序生成场景和 SVG：

1. 原尺寸画布；
2. 可编辑的干净底图 `<image data-layer-type="raster-background">`；
3. 按 `zIndex` 放置透明非文字元素；
4. 放置原生形状；
5. 按文字结构数据放置可编辑文字；
6. 写入稳定元素 ID、来源引用和必要变换；
7. 生成预览并进入回渲染 QA。

SVG 中复杂元素仍是可移动、替换和变换的 `<image>` 图层，不宣称其内部路径可编辑。

## 9. Provider 端口与候选路由

领域能力依赖端口，而不是型号：

```ts
interface VisionAnalyzerPort {
  analyze(input: AnalyzeInput): Promise<SceneAnalysis>;
}

interface ImageEditPort {
  redrawElements(input: ElementRedrawInput): Promise<ImageEditOutput>;
  repairBackground(input: BackgroundRepairInput): Promise<ImageEditOutput>;
}

interface RasterProcessorPort {
  prepare(input: RasterPreparationInput): Promise<RasterPreparationOutput>;
  detectAndCrop(input: DetectAndCropInput): Promise<CroppedElement[]>;
  compose(input: ComposeInput): Promise<ComposedAssets>;
}
```

首轮候选路由：

- GPT-5.6：结构识别和 JSON 输出；
- GPT Image 2：高保真编辑与底图补全；
- GPT Image 1.5：需要直接透明背景输出的元素重绘；
- GPT Image 2 + chroma key：透明输出不可用时的受控候选。

这些型号只进入部署 Profile、测试证据和 Provenance，不进入公共请求 Schema。任何
路由替换必须通过相同固定评测集。

## 10. 存储与交付

输入优先采用一次性上传或短期签名 URL。服务必须防御 SSRF，不允许任意内网地址、
重定向绕过、无限响应或未验证媒体类型。

输出支持两种模式：

1. `managed`：服务短期托管，返回有时效的下载 URL；
2. `presigned-put`：调用方提供受限目标，服务直接交付到调用方存储。

所有 AssetRef 至少包含 `id`、`mimeType`、`byteSize`、`sha256`、尺寸和获取方式。
队列消息只传 Conversion ID 和 Schema 版本，不传图片字节或完整 Manifest。

## 11. 幂等、取消、重试与费用

- 提交幂等由 Key、请求指纹和调用方身份共同约束；
- Worker 使用 claim/lease，至少一次投递不产生重复提交；
- 模型调用默认不盲目自动重试，未知供应商结果进入 `billing-uncertain`；
- 元素级失败允许只重试失败批次，不重复重绘全部元素；
- 取消阻止新的阶段和外部调用，但保留已完成事实和已知费用；
- 显式 retry 创建新 attempt，并引用原 Conversion；
- Usage 区分视觉分析、元素重绘、底图补全和确定性处理成本。

Media Service 返回实际 Usage Receipt。Muses 在调用前预留外层费用，在接收 Receipt
后结算；两者通过 `correlationId` 和 `providerExecutionId` 关联。

## 12. 安全与隐私

- Provider 凭证只存在于服务端适配器；
- 输入、输出和中间产物按租户调用凭证隔离；
- 日志禁止记录图片字节、签名 URL 查询参数和完整 Prompt；
- 上传限制类型、尺寸、解压后像素和总字节数；
- 内容安全阻断必须返回稳定机器码；
- 临时产物具有明确 TTL 和清理回执；
- callback 使用签名、时间戳和重放保护；
- 自托管模式与官方服务使用相同公共协议。

## 13. Muses 宿主适配

Muses Adapter 的职责顺序：

```text
authorize workspace/project/source asset
-> reserve credits
-> submit conversion with idempotency key
-> observe/poll signed result
-> verify hashes and manifest schema
-> ingest output assets
-> record provenance and usage
-> map manifest to DesignDocument command
-> place document/artifact through Operation Gateway
-> settle or release credits
```

Manifest 到 DesignDocument 的映射属于 Muses，不属于媒体服务。失败时不能先写客户端
画布再补记服务端状态。

## 14. 回渲染 QA 与验收指标

固定评测集至少覆盖：海报、社媒图、演示页面、信息图、UI 截图、复杂背景、中文和
英文混排、旋转文字、阴影、半透明元素、Logo、图表和大量小元素。

每个样本记录：

- 元素检测 Precision/Recall；
- OCR 字符准确率和文本块完整率；
- `logicalBBox` 偏差和层级顺序正确率；
- Alpha 泄漏、色边和裁切完整率；
- 底图残留元素与补全伪影率；
- 重组预览与原图的像素/感知差异；
- Logo、数字、图表等关键内容改变率；
- 成功率、部分成功率、P50/P95 延迟和单位成本；
- 取消、重试、崩溃恢复和幂等费用正确性。

Provider Spike 的最低逐元素门为：近色键泄漏率 `<=1%`、逻辑框与检测框宽高比漂移
`<=12%`、主体不得触及安全生成框边界、等比缩放漂移 `<=25%`、模型输出与对应源裁切
的外观相似度不得明显过低、非容器图层不得出现近乎全不透明的矩形边缘，且所有
`critical` 元素必须通过。任一绝对失败项都只能产出 `partial`/`failed`，不能依靠全局
相似度或“检测到了 asset”覆盖。

重绘批次不能把所有 `parentId=null` 的根节点当成同一上下文；根节点仅在空间相邻时
允许合批，默认优先局部单元素/同一父容器的小批次。这样可以防止多个不相邻模块被模型
重新设计成一张新页面。批次失败后只重试对应元素或局部批次，不回退到整页重绘。

首轮阈值不在没有数据时拍脑袋冻结。实现前先建立样本集和测量程序，基线跑完后由
产品负责人批准产品门槛。

## 15. 分阶段开发计划

当前阶段状态：

1. **Contract Gate**：基础 Manifest 与场景类型已形成；公共 HTTP 契约仍未冻结。
2. **Deterministic Core Gate**：测试图的栅格提取、SVG 组装、回渲染和结构测试已通过。
3. **Provider Spike Gate**：v2 真实调用已形成失败回归样本；当前正在重构场景角色、局部批次、透明化、比例保护和逐元素 QA，未重新通过。
4. **Job Gate**：实现持久 Conversion、attempt、lease、取消、重试和 Usage。
5. **Standalone API Gate**：完成独立启动、OpenAPI、认证和对象交付。
6. **Muses Integration Gate**：通过 Client、Asset 和 Command 生成 DesignDocument。
7. **Product Gate**：Studio/Agent/API 共用同一 Capability，随后评估工作流节点。

每个 Gate 必须有独立证据，不能以最终演示截图替代契约和故障验证。
