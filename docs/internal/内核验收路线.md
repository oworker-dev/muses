# 内核验收路线

## 1. 目的

平台优先不等于先造一个庞大框架。每个内核都必须以可运行证据证明抽象成立，业务场景只作为验收夹具，不进入内核代码或协议。

建设顺序不是直接进入 Wave 0：先完成 Value Foundation 确认用户任务、体验承诺、指标和停止规则；再通过 Technical Discovery 原型验证会改变契约语义的文档协作、画布/媒体与持久执行路线；最后才冻结 Wave 0 契约。

## 2. 三层验收门

### Gate A：独立运行

模块拥有明确输入输出、最小 Playground 或测试 Harness、无隐式全局依赖，并能在不启动完整产品场景的条件下完成核心行为。失败、空输入、取消和版本不兼容都有可观察结果。

### Gate B：协议复用

模块只能通过公开契约被调用。至少两个不同调用方使用相同接口，契约测试对内存实现和真实适配器同时运行。替换供应商或 UI 不改变上游领域模型。

### Gate C：跨模块组合

模块至少接入三种入口中的三种：交互界面、Agent、工作流、开放 API/插件；输出进入共享 Artifact/Asset/Job/Command 体系，具备来源、权限、幂等、取消或撤销等适用语义。

通过 Gate C 后才可称为“平台级可复用模块”。

### Gate V：用户价值成立

模块必须进入至少一个真实交付并改善预先声明的价值指标，同时不突破成本、自由、可靠性和安全护栏。Gate V 可以与 Gate A–C 并行收集证据，但不能被技术测试替代。没有价值改善的通用模块不得因“未来可能需要”无限打磨。

## 3. 建设波次

### Value Foundation：价值与体验基线

记录创始动机、目标用户、关键任务、体验承诺、用户所得、商业假设、北极星与护栏指标、证据阶梯和停止规则。

退出条件：[产品价值宪法](../shared/价值宪法.md)与[开放原则](../shared/开放原则.md)成为公开权威文档；AI 短剧和 PPT 当前工作流至少建立可测基线；关键价值假设具有负责人、证据级别、下一实验和决策阈值。

### Technical Discovery：关键技术路线

只验证会改变长期契约语义的技术路线，不提前选定完整技术栈：文档状态/协作、画布与文本/媒体渲染、浏览器与 Worker 分工、Job/Workflow 持久执行、Schema/序列化和事务/对象提交一致性。

退出条件：关键路线有可运行原型、体验与性能证据、淘汰理由、可逆边界和 APCC 决策；Wave 0 契约不泄漏选定库或供应商类型。

### Wave 0：协议实验室

目标是冻结最小语义而非完整功能：

- CreativeDocument、Artifact、Asset 引用与 Schema 迁移。
- Command、Revision、差异、逆命令和幂等。
- Capability Manifest、调用信封和结构化错误。
- Job 状态机、事件、取消、重试和 Provenance。
- 租户、权限与 correlation ID 贯穿链路。

退出条件：内存 Harness 和 PostgreSQL/S3/Queue 适配器共享契约测试；旧 Schema 样例可迁移；重复提交不产生重复副作用。

### Wave 1：文档与最小画布

实现无限视口、画板、图片、文本、形状、选择、变换、层级、自动保存、撤销/重做和修订。画布只投影 CreativeDocument，人工操作全部生成 Command。

退出条件：大型样例满足阶段性能预算；刷新后状态一致；同一命令可由 UI 和测试 Harness 执行；冲突与过期基线有明确结果。

### Wave 2：资产、任务与首个图像能力

打通上传、预签名访问、派生资产、缩略图、Job 进度、取消、重试和来源。首个建议能力是背景移除或受控图像变换，因为输入输出与质量判断清晰。

退出条件：能力可独立调用并将结果作为 Artifact 放回画布；供应商模拟与真实适配器共享测试；失败不会留下悬空权威状态。

### Wave 3：Agent 与画布工具

Agent 能读取受限项目上下文和选择快照，通过 Capability 生成资产，通过 Command 放置或修改对象；具备预算、确认、暂停、恢复和检查点。

退出条件：Agent 不拥有数据库写旁路；工具版本固定；每步可追踪；拒绝确认和预算耗尽能够安全停止；已提交画布变更可撤销。

### Wave 4：工作流与三入口证明

实现版本化 DAG、类型化端口、Capability 节点、Agent 节点、人工审批、并行、重试和运行快照。

退出条件：同一图像能力由 UI、Agent、Workflow 三种入口成功调用，结果语义一致；工作流重放绑定精确版本；重复事件不造成重复产物或收费。

### Wave 5：专业媒体与组合套件

在共享协议上增加视频时间轴、音频与音乐轨道、演示分页、品牌约束、批量变体与发布能力。每个媒体模块先完成 Gate A，再进入跨媒体组合。

退出条件：图像、视频、音频/音乐和演示保持自己的编辑语义，同时共享资产、任务、来源、权限和成本；场景模块仅通过组合实现 AI 短剧与 PPT 定制等至少两条端到端生产链路。

## 4. 首个架构证明

首个垂直证明不是完整电商产品，而是一条最小跨入口链路：

```text
上传图片
  → 创建 Asset 与图片 Artifact
  → 调用 background.remove Capability
  → Job 产生带来源的派生 Asset
  → Command 将结果放入 CreativeDocument
  → 用户撤销/重做放置
```

同一 Capability 必须分别由：

1. 画布操作面板调用；
2. Agent Tool 调用；
3. Workflow Node 调用。

三条路径必须共享 Manifest、策略、Job、资产提交和 Provenance，不允许复制业务逻辑。

## 5. 每个内核的交付物

- 一页职责、非职责、权威数据与依赖说明。
- 版本化类型/Schema 和兼容策略。
- 参考内存实现或测试替身。
- 至少一个真实适配器。
- 契约、状态机、迁移、安全与故障测试。
- 最小 Playground/Harness。
- 指标、日志、追踪与成本字段。
- 已知限制和下一次重审条件。

## 6. 质量计分卡

| 维度 | 必须回答的问题 |
| --- | --- |
| 独立性 | 是否能脱离具体场景运行和验证？ |
| 复用性 | 是否至少有两个真实调用方且没有复制逻辑？ |
| 组合性 | 是否通过标准标识、Schema、Job、Command 或事件连接？ |
| 可恢复性 | 失败、取消、重试、重复投递和断线后会怎样？ |
| 可演进性 | 旧数据、旧工作流和旧调用方如何兼容？ |
| 安全性 | 租户、权限、敏感数据和外部副作用在哪里校验？ |
| 可解释性 | 输入、模型、参数、操作者、成本和产物能否关联？ |
| 可替换性 | 更换供应商或实现是否不改变上游领域语义？ |
| 可运营性 | 是否有 SLO、指标、诊断、配额和成本归因？ |
| 用户价值 | 是否改善真实任务的速度、质量、控制、自由度或成功交付成本？ |
| 开放自由 | 是否可由公开源码验证，并支持结构化导出、迁移或自托管边界？ |

任何一项没有明确答案，模块都不能进入稳定内核层。

## 7. 场景夹具规则

AI 短剧、PPT 定制、电商、短视频和品牌可以用于发现需求与验收组合价值，但必须遵守：

- 场景类型只存在于场景层或配置中。
- 场景不得直接访问内核数据库表或供应商 SDK。
- 被两个场景重复需要的行为先判断是否属于已有 Capability，而不是立即新增“通用”抽象。
- 只有经过至少两个差异明显的调用方验证后，场景抽象才提升为平台契约。
- 场景交付压力不能跳过来源、权限、幂等、迁移和租户隔离。
- 场景实验必须在开发前记录基线指标和停止阈值，开发后记录真实交付结果。
- 创始人业务是首批证据但不是永久唯一证据；必须持续邀请外部目标用户复现。

## 8. APCC 管理方式

Value Foundation、Technical Discovery 和每个 Wave 建立独立 APCC Plan；每个 Gate 建立可验收 Task。范围、架构、开放政策与许可证变化记录 Decision；稳定里程碑记录 Version；实现证据、价值实验和风险写入 `delivery/`。计划状态以任务自动推导，不在文档中手工维护百分比。
