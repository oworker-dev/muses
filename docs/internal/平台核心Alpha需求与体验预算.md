# 平台核心 Alpha 需求与体验预算

## 1. 文档目的

本文把“工作流原生画布可用”“两层画布流畅”“保存恢复可靠”等主观目标变成 Gate 0 可以重复验证的产品契约。它约束候选技术 Spike 和后续 Platform Core Alpha 实现，但不预先选择画布库、渲染技术、状态库或 Agent SDK。

这些数值是首轮工程预算，不是永久上限。只有真实测量证明某项预算不合理时，才能通过 APCC 决策调整；不得为了让候选实现通过而静默降低门槛。测试报告必须同时保留设备、浏览器、构建版本、数据集、测量方法和原始结果。

## 2. Alpha 用户承诺

Platform Core Alpha 必须让单个桌面用户在没有 Agent 的条件下完成以下工作，并始终知道“现在在哪里、系统在做什么、什么已经保存、什么可以撤销、结果从哪里来”：

1. 在工作流无限画布中创建输入、能力和专业文档节点。
2. 区分上下文、来源、关联、数据流和控制关系，不把探索连线误当作已发布工作流。
3. 发起图像任务，观察排队、运行、成功、失败和取消状态。
4. 在组合测试夹具中比较三个固定结果分支并选择其中一个，同时保留未选结果及其来源；正式生图默认数量为 1，多结果和人工选择必须由用户显式配置。
5. 进入 `DesignDocument`，编辑文本、图片和基础形状，再返回原外层视口。
6. 撤销或重做对应层级的修改，不发生跨层误撤销。
7. 刷新或重新打开项目后恢复已确认状态、选择、分支、任务和来源记录。
8. 导出不依赖候选画布库内部类型的结构化项目。

Alpha 不承诺移动端、多人实时协作、完整专业设计工具、通用工作流自动化、视频/音频时间线或 PPT 编辑体验。Alpha 只提供发布合法性校验与后端耐久运行边界 Probe，不能把它描述为完整工作流执行器。

## 3. 场景无关验收夹具

### 3.1 标准闭环 `PC-A01`

所有候选实现和正式 Alpha 使用同一条确定性链路：

```text
Start 节点（类型化输入变量）
→ ImageTransform Capability 节点
→ 三个结果 Asset 分支
→ Compare/Select 节点
→ DesignDocument 专业节点
→ 发布一个设计输出端口
→ End 节点
```

`PC-A01` 是覆盖分支、集合、人工等待和两层画布的组合测试夹具，不是专业模式默认模板，也不规定真实图像模型必须输出三个“方向”。正式首图最小模板、节点理由和目标契约以[专业模式节点产品目录](专业模式节点产品目录.md)为准：`Start → image.generate → End`，`count` 默认 1，`human.review` 与 `document.design` 按用户意图显式添加。

用户必须完成：

1. 打开项目，平移、缩放并定位输入区域。
2. Start 与 End 已存在且不可重复创建或删除；在 Start 定义文本、数字和布尔输入，再创建能力、比较选择和 `DesignDocument` 节点。
3. 分别创建 `context`、`dataflow` 和 `association` 边，并从来源面板观察系统生成的 `provenance` 边。
4. 尝试一条类型不兼容连接，系统必须拒绝并解释原因，且不得改变权威文档。
5. 运行确定性 `ImageTransform` 测试能力，观察 `queued → running → succeeded`。
6. 比较三个固定结果，选择一个结果；选择是显式 Command，而不是临时 UI 状态。
7. 进入 `DesignDocument`，新增文本和形状、替换图片、移动对象、撤销并重做一次。
8. 退出专业节点，恢复进入前的外层视口、选择上下文和键盘焦点锚点。
9. 将专业文档显式发布的输出端口连接到 End 节点。
10. 等待保存确认，刷新页面并核对图、内层文档、修订、选择、Job 和 Provenance。
11. 通过发布校验后获得真实后端 `runId`，查询到完成的耐久 Probe；再导出结构化项目，确认不含候选库专有节点、事件或序列化类型。

### 3.2 Start、End 与发布校验

- 一个可发布定义必须恰好包含一个 Start 和一个 End；二者不能从节点库重复添加，也不能删除。
- Start 的输出端口只能从类型化输入变量派生。Alpha 至少支持 `text`、`number` 和 `boolean`，变量标识稳定且变量名称唯一。
- 发布校验必须覆盖端口存在性、类型、必填绑定、重复绑定、悬空边、隐式执行环、Start 到 End 可达性，以及每个定义期执行节点是否位于 Start→End 路径。
- 发布产生稳定拓扑顺序。运行期 `image-result`、Asset 和 provenance 投影不参与定义期拓扑。
- 浏览器本地夹具不等于 Workflow SDK 运行。只有后端 SDK 返回并能查询的 `runId` 才能显示为耐久运行。

### 3.3 确定性测试能力

Gate 0 不调用付费模型。`ImageTransform` 使用可重复的本地/测试适配器：固定输入与参数总是得到三个固定 Asset 引用，运行延迟和故障可以注入。它必须明确标注“本地图像夹具”，并使用与未来真实图像提供商相同的 `Capability → Job → Asset → Provenance` 公共端口；它不能成为 UI 私有 mock，也不能冒充 Workflow SDK 执行。

三个固定 Asset 仅用于测试可重复性。测试适配器的数量、占位图和人工 Selector 不得成为正式 `image.generate` 的默认配置、用户不可修改的行为或公共 DSL 限制。

测试适配器至少支持：

- 可配置的排队、进度和完成延迟。
- 成功、提供商失败、超时、断网、取消竞态和迟到结果。
- 幂等提交：重复同一提交键不会创建第二次权威执行或重复计费记录。
- 显式重试：创建可追踪的新 attempt，并引用原 Job。
- 固定成本单位，用于验证预算展示和成本归因，不代表真实货币价格。

### 3.4 数据规模档位

| 档位              | 外层节点 | 外层边 | 当前可见节点 | 单个 DesignDocument 对象 | Asset 引用 | 用途                                 |
| ----------------- | -------: | -----: | -----------: | -----------------------: | ---------: | ------------------------------------ |
| `F0 功能集`       |       20 |     30 |           20 |                      100 |         30 | 每次提交的功能、键盘和故障回归       |
| `A1 Alpha 目标集` |      500 |    750 |          150 |                    1,000 |        500 | Gate 0 与 Alpha 发布的强制规模门     |
| `S2 压力集`       |    2,000 |  3,000 |          300 |                    5,000 |      2,000 | 发现退化拐点；本阶段不作为发布阻断门 |

二进制媒体不得内嵌在 WorkflowDocument 或 DesignDocument 中，只保存 Asset 引用和必要元数据。视口外对象可以虚拟化，但选择、搜索、连接、序列化、撤销和来源语义不得因不可见而丢失。

`A1` 是最低支持规模，不是长期产品上限。若 Spike 无法通过，必须记录瓶颈和缩减影响，由产品负责人决定削减 Alpha 范围或更换技术路线；不得只在 `F0` 上宣称画布可用。

## 4. 测量基线

### 4.1 参考环境

强制报告至少覆盖以下参考档位：

- 桌面视口：`1440 × 900`，设备像素比 `1`；另做 `1280 × 720` 布局检查。
- 设备能力：4 个 CPU 核心、8 GiB 内存、集成显卡级别；不得只使用高端开发机结果。
- 浏览器：测试时的最新稳定 Chromium，报告精确版本；Firefox 和 Safari 先做兼容性冒烟，不作为 Gate 0 性能基准。
- 网络：API 测试同时记录本机基线和 `100 ms` RTT、下行 `20 Mbps`、上行 `5 Mbps` 的受控网络档位。
- 构建：生产构建、关闭 React 开发模式和浏览器扩展；保留 trace、长任务、内存和关键请求记录。

如果 CI 无法稳定模拟参考设备，性能 Gate 在固定参考机执行，CI 只负责功能和相对退化检测。任何跨版本比较必须使用同一设备、浏览器主版本、数据集和测量脚本。

### 4.2 统计规则

- 交互延迟至少执行 30 次并报告 `p50/p95/p99`，不以最好一次结果代替。
- 加载、保存和恢复至少执行 10 次；故障场景至少连续执行 5 次。
- 帧性能至少采样连续 10 秒的平移、缩放和拖动过程。
- 首次冷加载与缓存后的暖加载分别报告。
- 所有“已保存”“已取消”“已恢复”都以服务端权威状态验证，不只检查界面文案。

## 5. 空间交互与导航预算

| 能力                     | `F0` 强制门                        | `A1` 强制门                  | 验证方式                             |
| ------------------------ | ---------------------------------- | ---------------------------- | ------------------------------------ |
| 平移、缩放、节点拖动     | 采样帧 `p95 ≤ 16.7 ms`，无连续卡顿 | `p95 ≤ 20 ms`，`p99 ≤ 50 ms` | Performance trace；连续 10 秒操作    |
| 指针到本地视觉反馈       | `p95 ≤ 50 ms`                      | `p95 ≤ 100 ms`               | 点击选择、框选、拖动开始和连接预览   |
| 点击/键盘选择节点        | `p95 ≤ 100 ms`                     | `p95 ≤ 150 ms`               | 从输入到选中样式和 Inspector 更新    |
| 搜索并定位已知节点       | `p95 ≤ 300 ms`                     | `p95 ≤ 500 ms`               | 搜索索引到视口聚焦，不含人工输入时间 |
| 打开节点命令面板         | `p95 ≤ 150 ms`                     | `p95 ≤ 250 ms`               | 暖状态，完整可交互                   |
| 创建/删除/连接的乐观反馈 | `p95 ≤ 100 ms`                     | `p95 ≤ 150 ms`               | 本地投影；必须显示未确认状态         |
| 撤销/重做本地投影        | `p95 ≤ 100 ms`                     | `p95 ≤ 200 ms`               | 外层和内层分别测量                   |

补充要求：

- 任何连续操作中不得出现超过 `200 ms` 的主线程长任务；超过 `50 ms` 的长任务每 10 秒最多 2 次，并必须能归因。
- 缩放级别、节点位置、选择、框选和连线手势不得依赖像素级精确点击；连接端口应有稳定的可命中区域和键盘替代路径。
- 边类型不能只靠颜色区分，必须同时使用线型、标记、标签或 Inspector 语义。
- 视口进入高密度区域时允许降级预览细节，但不能丢失节点身份、状态、端口兼容性或错误信息。

## 6. 两层画布体验预算

| 能力                       | 预算                                             | 必须保持的上下文                             |
| -------------------------- | ------------------------------------------------ | -------------------------------------------- |
| 打开 `DesignDocument` 外壳 | 暖开 `p95 ≤ 300 ms`；冷开 `p95 ≤ 1,000 ms`       | 外层 document、node、revision 和来源入口     |
| 目标规模专业文档可交互     | `A1 p95 ≤ 2,000 ms`                              | 图层列表、选择、缩放、撤销可用               |
| 内层文字输入反馈           | `p95 ≤ 50 ms`                                    | 输入法组合期间不得提交不完整 Command         |
| 内层选择/移动/缩放反馈     | `p95 ≤ 100 ms`                                   | 对齐和变换投影不能修改外层节点位置           |
| 退出并恢复外层             | `p95 ≤ 300 ms`                                   | 进入前视口中心、缩放、选择和焦点锚点         |
| 更新外层预览               | 保存确认后 `p95 ≤ 1,000 ms`                      | 预览可延迟但必须标注旧修订，不得冒充权威状态 |
| 专业文档分支               | 本地反馈 `≤ 150 ms`，服务端确认 `p95 ≤ 1,000 ms` | 新分支保留父 revision 与 provenance          |

进入专业文档是同一创作空间中的聚焦模式，不是丢失上下文的页面跳转。浏览器返回、显式退出和面包屑都必须回到同一外层位置。外层快捷键在内层编辑时不得误触发，文字输入、画布手势和全局命令必须有清晰事件优先级。

## 7. 保存、修订与恢复预算

### 7.1 状态可见性

界面始终显示以下互斥状态之一：`已保存`、`正在保存`、`本地待同步`、`保存失败`。不能在服务端确认前显示“已保存”。每个持久 Command 带目标文档、预期 revision、idempotency key、actor 和 correlation ID。

### 7.2 时间与数据保证

| 行为                         | 预算/保证                                                              |
| ---------------------------- | ---------------------------------------------------------------------- |
| 空闲自动保存启动             | 最后一个可合并操作后 `≤ 1,000 ms`                                      |
| 单个 Command 服务端确认      | 本机 `p95 ≤ 500 ms`；受控网络 `p95 ≤ 1,500 ms`                         |
| 手动保存/离开前 flush        | 受控网络 `p95 ≤ 2,000 ms`；超时必须阻止静默离开或明确征得用户确认      |
| `F0` 冷刷新恢复到可交互      | `p95 ≤ 2,500 ms`                                                       |
| `A1` 冷刷新恢复到可交互      | `p95 ≤ 5,000 ms`；首屏骨架/进度 `≤ 500 ms`                             |
| 已确认 Command 数据丢失      | `0`                                                                    |
| 浏览器崩溃后的本地待同步命令 | 重开后必须恢复并提示继续同步或放弃；不得静默丢失                       |
| 过期 revision                | 服务端拒绝且不覆盖新状态；受控网络 `p95 ≤ 1,500 ms` 返回可操作冲突信息 |

Alpha 是单用户产品阶段，不实现 CRDT/OT，但必须正确处理双标签页或迟到请求造成的过期 revision。冲突后保留用户未提交意图，允许刷新、重放或显式放弃；禁止 last-write-wins 静默覆盖。

### 7.3 撤销边界

- 外层 `WorkflowDocument` 与内层 `DesignDocument` 分别维护命令历史和 revision。
- 用户在当前焦点层撤销；跨层复合意图通过 correlation ID 展示关联，但不形成不可恢复的隐式事务。
- 已成功产生外部副作用的 Job 不能靠普通撤销“假装没发生”；撤销只移除引用或选择，取消/补偿使用显式命令并保留审计。
- 刷新后至少恢复当前会话最近 100 个可撤销本地命令，或明确标注因已压缩 revision 不能继续撤销的边界。

## 8. Job、Capability 与故障体验预算

| 场景             | 用户可见行为                                               | 时间/一致性门槛                                    |
| ---------------- | ---------------------------------------------------------- | -------------------------------------------------- |
| 正常执行         | 状态、阶段进度、能力版本、成本单位可见                     | 服务端变化后受控网络 `p95 ≤ 1,500 ms` 投影到 UI    |
| 用户取消         | 立即显示“正在取消”，最终进入已取消或明确说明无法取消       | 本地反馈 `≤ 100 ms`；适配器确认后 `p95 ≤ 1,500 ms` |
| 取消与成功竞态   | 保留真实完成事实，但不得自动选用用户已取消意图下的迟到结果 | 每次测试结果一致且 provenance 完整                 |
| 提供商失败       | 保留输入与已完成结果，显示可理解原因和重试入口             | 错误到达后 `p95 ≤ 1,500 ms`；不得留下永久 running  |
| 超时/Worker 重启 | Job 可恢复、失败或进入待人工处理，不重复提交副作用         | 重启后 `≤ 10 s` 达到可解释终态或恢复运行           |
| 重复提交         | 返回同一权威 Job/attempt                                   | 不创建重复 Asset、成本或外部调用                   |
| 显式重试         | 新 attempt 引用原 Job，旧失败事实不被覆盖                  | 参数、能力版本和成本分别可追踪                     |
| 网络中断         | `≤ 2 s` 显示连接问题；本地编辑进入待同步                   | 恢复后按 revision 顺序同步，冲突不静默覆盖         |

错误信息必须包含：发生了什么、哪些状态仍安全、是否产生费用、用户现在能做什么。原始提供商错误和密钥信息不得直接暴露给终端用户。

## 9. 可访问性与输入方式

Alpha 的产品壳、Inspector、命令面板、节点列表和专业文档基础控件以 WCAG 2.2 AA 为目标。无限画布不能成为只有鼠标用户才能操作的黑盒。

强制门：

- 仅使用键盘完成 `PC-A01` 的创建、连接、运行、结果选择、进入/退出专业节点、编辑基础对象、保存和恢复；拖动操作必须有命令面板或 Inspector 替代路径。
- 提供与画布同步的可聚焦节点/边列表或结构视图，使屏幕阅读器可以读取节点名称、类型、状态、端口、连接和错误。
- 焦点顺序稳定；进入专业文档时焦点进入明确标题/画布入口，退出时回到原节点。
- 所有交互元素具有可见焦点；常规文本和控件满足 AA 对比度，边语义不只依赖颜色。
- 浏览器缩放到 `200%` 时，核心命令、状态、错误和保存入口不丢失；`1280 × 720` 下无阻断性遮挡。
- 支持 `prefers-reduced-motion`，平移定位和模式切换不以大幅动画作为唯一反馈。
- 快捷键可发现、可重映射冲突项，且不覆盖浏览器、输入法或辅助技术的关键组合键。

自动化使用 axe 等规则检查，但 Gate 0 还必须完成一次纯键盘人工走查和至少一次主流屏幕阅读器结构走查。未通过时可以削减快捷操作，不能删除替代操作路径。

## 10. 资源与稳定性预算

在参考环境和生产构建中：

- `A1` 数据集稳定后 JS heap 目标 `≤ 750 MiB`；报告 DOM 节点、Canvas/WebGL 资源和图片缓存占用。
- 连续执行 20 次“进入 DesignDocument → 编辑 → 退出”和 20 次项目切换后，强制回收后的 heap 不得相对首轮稳定值持续增长超过 `10%`。
- 连续操作 30 分钟不得崩溃、白屏、丢失已确认 Command 或产生无法解释的 revision 分叉。
- 资产缩略图必须按需加载并有尺寸/数量边界；失败或离屏时释放可重建资源。
- Worker、网络或浏览器标签页中断后，服务端权威文档保持可读，Job 不出现无法恢复的永久中间态。

内存预算是退化警戒线，不是鼓励占满 750 MiB。若候选库在 `F0` 就超过 300 MiB 或出现持续泄漏，应优先淘汰或隔离，而不是等到 `A1` 再优化。

## 11. Gate 0 证据包

每个候选实现必须提交同结构证据，建议存入 `delivery/evidence/platform-core-alpha/gate-0/<candidate>/`：

1. 候选版本、许可证、维护状态、包体积和已知限制。
2. Muses 领域对象到候选库投影层的边界说明。
3. `F0` 与 `A1` 的功能结果、trace、长任务、内存、加载和恢复数据。
4. `S2` 的退化曲线和首个明显拐点，不要求通过全部预算。
5. `PC-A01` 屏幕录像或可复现脚本。
6. 键盘、焦点、结构视图和屏幕阅读器走查记录。
7. 断网、过期 revision、重复提交、取消竞态、Worker 重启和浏览器崩溃结果。
8. 序列化样本以及“不包含候选库专有类型”的自动检查。
9. 采用、组合或淘汰建议，列出仍未知风险和下一次验证成本。

同一失败连续出现三次才视为稳定失败；偶发异常必须保留原始记录，不能从统计中删除。候选比较使用同一夹具、数据生成器和测量脚本。

## 13. 退出与变更规则

本需求任务完成的条件：

- `PC-A01`、`F0/A1/S2`、参考环境和统计规则已经固定。
- 交互、两层画布、保存恢复、Job 故障、可访问性和资源预算都有可测门槛。
- 下一步技术栈短名单必须使用本文，而不是候选库 Demo 作为比较标准。

Gate 0 只有在至少一个实现满足 `F0` 全部强制门、满足 `A1` 的核心交互/恢复门，并能说明其余差距如何在 Alpha 内关闭时才可退出。涉及用户数据丢失、命令写旁路、跨层权威状态混淆、序列化锁定或核心链路无键盘替代的失败是硬阻断项，不能以性能更高抵消。

预算变更必须同时更新本文、APCC 任务或决策、相关自动化和历史证据说明。不得重写旧测试结果使其看似满足新预算。
