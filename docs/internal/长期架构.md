# 长期架构

## 1. 文档地位

本文定义项目在多年演进中应保持稳定的架构意图。它规定领域边界、依赖方向、交互语义和质量门，不冻结当前框架、供应商、部署拓扑或目录结构。

修改本文中的核心原则、内核职责、权威数据所有权或跨内核协议，必须先创建 APCC `architecture` 决策；普通实现选择写入相应模块文档即可。

## 2. 架构原则

1. **内核优先，场景组合**：业务场景组合通用能力，不向内核注入电商、PPT 或社媒特例。
2. **契约优先，实现可替换**：跨边界依赖版本化契约，不依赖供应商 SDK、数据库表或 UI 内部状态。
3. **一个事实来源，一个明确所有者**：每类权威状态只由一个内核拥有，其他模块通过标识符、查询或事件引用。
4. **命令统一，入口平等**：用户、Agent、工作流与 API 修改创作状态时采用相同命令语义、校验、授权和审计。
5. **异步优先设计**：模型生成、视频处理和批量任务天然是长任务；取消、重试、恢复、幂等和中间结果不是后补功能。
6. **来源与成本是一等数据**：每个衍生成果都能回答由谁、何时、用什么输入、模型、参数、授权和成本产生。
7. **本地响应，服务端权威**：高频编辑可以乐观执行，持久协作状态由服务端确认并支持冲突处理与重放。
8. **先模块化单体，按证据拆分**：逻辑内核先通过包边界与进程边界隔离；只有扩缩容、故障域、安全或团队所有权证据充分时才拆服务。
9. **抽象接受组合检验**：无法独立运行、无法被多个入口复用或无法与相邻内核组合的“通用模块”不算成熟。
10. **安全与可访问性内建**：租户隔离、最小权限、内容安全、隐私、版权和无障碍是设计输入，不是发布前清单。
11. **价值先于技术完美**：架构与模块必须服务明确用户任务和可测价值；没有价值证据的复杂度应被停止或删除。
12. **开放是产品性质**：核心源码、协议、格式和迁移路径默认公开；用户数据默认私密，官方服务不以锁定用户获利。
13. **Agent 与 Workflow 是独立产品**：通用 Agent 首先作为 Web-first 项目独立发布和运行，Workflow Engine 独立拥有定义、编译、发布和耐久执行；二者只通过公开工具和 `agent.run` 端口组合。
14. **Muses 是 Agent 的第一个宿主**：画布、资产、媒体、Workflow、身份和计费以 Host tools/slots 注入通用 Agent。Agent 离开 Muses 后仍必须通过独立 Web 应用完成通用自主任务。
15. **创作产品与平台控制面分离**：Studio 面向创作任务，平台控制面管理模型供应、能力、价格、路由和用量；共享身份、审计和基础设施不等于混合用户心智。
16. **付费执行先授权再预留**：真实模型调用前必须确认会话、工作区权限和可用积分，并以幂等预留、实际结算和释放闭环外部费用。

## 3. 系统分层与依赖方向

```text
体验与场景层
  Agent-first 无限创作空间 / 专业工作流 / 项目与品牌 / AI 短剧 / 电商 / 演示 / 社媒 / 开发者接口
                              ↓ 只组合能力
专业文档层
  DesignDocument / PresentationDocument / VideoDocument / AudioDocument / FutureDocument
                              ↓ 通过公开端口连接外层
创作能力层
  图像 / 视频 / 音频与音乐 / 排版 / 文档 / 品牌 / 发布 / 导入导出
                              ↓ 声明 Capability
执行内核层
  Standalone Agent Runtime / Workflow Runtime / Capability Registry / Model Catalog / Job Runtime / Policy
                              ↓ 产生命令、任务与产物
创作内核层
  Creative Document / Canvas Projection / Asset / Version / Provenance
                              ↓ 使用平台端口
平台基础层
  Identity / Tenant / Credit Ledger / Billing / Storage / Database / Queue / Realtime / Observability
                              ↓
供应商适配层
  Model / Media Processor / Storage / Queue / Publish Channel adapters
```

依赖只能向下指向契约；事件可以向上通知事实，但不能把下游业务类型泄露回内核。场景模块可以引用内核标识符，内核不能引用场景类型。

## 4. 权威领域对象

| `Project`              | 项目上下文   | 一次持续创作活动及其品牌、素材和成员上下文                        |
| `CreativeDocument`     | 创作文档内核 | 跨媒体文档家族的共同信封、稳定标识、修订引用和迁移规则            |
| `CreativeCanvas`       | 创作画布内核 | 资产、结果、空间关系、AgentThread/Run 投影和来源引用              |
| `ProfessionalWorkspace` | 工作流图内核 | 多个独立 WorkflowDefinition 的总览、布局和编辑上下文              |
| `ProfessionalDocument` | 专业文档内核 | Design、Presentation、Video、Audio 等专业文档的共同引用与扩展边界 |

| `UsageRecord`          | 计量内核     | 模型实际用量、价格快照、预计/实际积分与执行关联                   |
| `CreditLedgerEntry`   | 计费内核     | 工作区积分发放、预留、结算、释放和退款的不可变事实                |
| `AgentSession`         | Agent 内核   | 用户目标、上下文连续性、消息与 Run 关联                           |
| `AgentRun`             | Agent 内核   | 一次有预算和权限边界的规划、工具调用与检查点序列                  |

| `WorkflowDefinition`   | 工作流内核   | 版本化节点图、输入输出、控制流和发布状态                          |
| `WorkflowDeployment`   | 工作流内核   | 已发布定义版本与稳定调用别名的绑定                                |

| `ProvenanceRecord`     | 来源内核     | 输入、输出、操作者、模型、策略、成本和授权的不可歧义关联          |

`Artifact` 与 `Asset` 必须区分：Artifact 是创作语义，Asset 是存储与媒体语义。一个 Artifact 可以引用多个 Asset 版本；同一 Asset 也可以被多个 Artifact 引用。

## 5. 核心内核

### 5.1 创作文档家族

负责跨媒体文档的共同信封、稳定标识、资产引用、修订引用和 Schema 迁移，但不把全部媒体细节塞入一个万能对象。`CreativeCanvas` 拥有默认创作空间；`ProfessionalWorkspace` 管理独立工作流定义；`DesignDocument`、`PresentationDocument`、`VideoDocument` 与 `AudioDocument` 等拥有各自专业状态。

文档内核不负责屏幕渲染、模型调用、业务模板或供应商文件格式。任何长期保存的编辑状态必须可版本化、可迁移，并保留明确扩展字段以支持前后兼容。跨文档引用使用稳定 ID 和修订，不通过共享可变内存对象耦合。

### 5.2 命令与版本内核

所有权威修改表达为命令。命令至少包含命令 ID、操作者、租户、目标、基线修订、载荷 Schema 版本、幂等键和因果上下文。命令处理结果包含接受状态、新修订、结构化差异、事件与可选补偿命令。

撤销不是简单删除历史：纯文档操作可使用逆命令；产生外部副作用的操作使用补偿语义。检查点和分支建立在已确认修订上，不依赖客户端临时状态。

### 5.3 工作流画布与专业画布

默认顶层画布是 `CreativeCanvas` 的无限空间投影和交互系统，负责坐标、视口、命中测试、选择、资产布局、AgentRun 状态、来源关系和大图虚拟化。它不显示开始/结束节点，也不把空间连线自动解释为可执行 DAG；每次用户需求由 `AgentRun` 提供隐式输入和终止边界。

专业模式投影 `ProfessionalWorkspace` 中的一个或多个独立 `WorkflowDefinition`。总览可以折叠多个定义；进入单一定义后才显示 Input/Trigger、Output/Return、类型化端口、控制流和调试状态。定义身份不能由节点坐标、开始节点 id 或连通分量推导。

创作边至少区分上下文、来源和普通关联；专业工作流边区分类型化数据流与控制依赖。只有通过端口、权限、版本、循环和副作用校验的 `WorkflowDefinition` 才能发布和执行。

`DesignDocument` 等专业文档在外层表现为拥有预览、修订和类型化端口的节点；聚焦后进入自己的专业画布。外层只能连接公开端口，不能直接连接内部图层、轨道或渲染对象。内部对象需要被外层消费时，由专业文档显式发布 Artifact、选择集或输出端口。

两层画布都不拥有领域真相，只通过对应文档的 Command 修改权威状态。移动外层专业节点与移动其内部对象是不同聚合上的不同命令；可以通过 correlation ID 关联，但不能混成一次隐式客户端写入。

### 5.4 资产与来源内核

资产内核管理上传、派生文件、代理文件、缩略图、格式、尺寸、校验和、存储位置、引用计数、保留策略和授权访问。来源内核把资产与输入、模型、参数、提示、操作者、时间、成本、内容安全结果及父资产关联。

数据库只保存逻辑元数据和对象键；客户端不得获得长期存储密钥；外部 URL 必须被视为可过期引用。

### 5.5 Job Runtime

所有长任务遵循统一状态机：

```text
created → queued → running → succeeded
                    ↘ failed
                    ↘ cancel_requested → canceled
failed → queued（显式重试，产生新 attempt）
```

Job 保存不可变输入快照、能力版本、执行尝试、进度事件、中间产物、最终输出、错误分类、资源用量和费用。至少一次投递是默认假设，因此执行器与提交阶段必须幂等；取消是协作协议，不是假定底层供应商一定能立即停止。

### 5.6 Capability Registry

能力是所有调用入口共享的最小扩展单位。声明至少包含：

```ts
type CapabilityManifest = {
  id: string;
  version: string;
  title: string;
  inputSchema: JsonSchema;
  outputSchema: JsonSchema;
  execution: "sync" | "async" | "stream";
  permissions: string[];
  sideEffects: "none" | "document" | "external";
  costPolicy?: CostPolicy;
  compatibility: CompatibilityRange;
};
```

Manifest 是产品契约，不暴露供应商 SDK 类型。能力实现通过适配器选择模型或处理器；策略层基于租户、地区、数据敏感度、预算、质量和可用性决定是否允许及如何路由。

Capability 与具体模型供应分开。`ModelOffering` 通过不可变 `modelRef` 关联供应商模型、`CapabilityProfile` 和适配器；`PriceBookEntry` 独立版本化。节点保存用户意图和稳定引用，不保存供应商密钥、Base URL、可变价格或 SDK 对象。详细控制面契约见[模型能力目录与平台控制面](模型能力目录与平台控制面.md)。

### 5.6.1 用户工作区与积分计量

Identity 验证“是谁”，Workspace 成员关系验证“可以操作什么”，积分账本验证“是否允许产生费用”。Studio 及其 API 不允许匿名调用生产模型；个人工作区是当前最小租户形态，不以 `userId` 取代长期 Workspace 身份。

付费 Job 在供应商调用前创建幂等积分预留，完成后依据运行绑定的 PriceBook 版本和实际 UsageRecord 结算并释放差额。失败、取消和未知供应商结果必须区分是否已经产生费用。Stripe 等法币支付未来只向积分账本产生幂等发放，不替代模型消费账本。详细边界见[用户工作区与积分计费边界](用户工作区与积分计费边界.md)。

### 5.7 Agent Runtime

Agent Runtime 属于一个可独立发布、部署和运行的 Web-first Agent 项目，负责会话、上下文装配、计划、模型循环、工具调用、预算、权限确认、流式事件、暂停、恢复、检查点和评估。它不依赖 Studio、Canvas、Workflow、媒体或场景模块；这些能力只能由宿主通过版本化 Tool、Skill、MCP 和 Host slots 注入。

Agent Runtime 采用 Harness adapter，而不是以 AI SDK/Chat SDK 作为内核。Eve 是平台级耐久 Harness 首选候选，Pi Agent Core 是轻量可嵌入对照候选；AI SDK 只负责模型、结构化输出、工具协议和流式 UI，Workflow SDK 只负责耐久步骤。Harness Session、消息、todo、checkpoint 与框架 state 都是运行证据或投影，不能成为 Project、CreativeDocument、Command、Asset、Job、Provenance 或 Policy 的权威状态。

每次 `AgentRun` 固定模型策略、工具版本、上下文摘要和预算上限。读取上下文与写入操作分离；删除、外部发布、高成本生成、敏感数据访问等操作由策略决定是否要求用户确认。

Agent 当前主要产品入口是独立 Web 应用；CLI 只承担开发、诊断和自动化。Web 应用、Client SDK、Host SDK 和服务端 Runtime 使用同一消息、事件、控制和 Usage 协议。Muses 是第一个 Host，平台 MusesAgent、领域 Agent 和工作流 Agent 节点都复用同一 Agent Runtime，不拥有数据库或画布写旁路。完整边界见[独立 Web Agent 项目与 Muses 宿主集成](独立WebAgent项目与Muses宿主集成.md)。

委托层级不是固定系统拓扑。MusesAgent 负责跨领域意图、澄清和委托；领域 Agent 由版本化知识、工具、策略和验收配置定义；SubAgent 是一次受控执行角色。真正的并发、依赖、预算、重试、取消、检查点、失败隔离、结果汇总与成本归因由 Runtime Scheduler 持有。

委派协议明确区分 root AgentRun、直接 parent AgentRun、DelegationRun 与 child AgentRun。子 Run 不继承父历史或父沙盒，只接收绑定父 ContextSnapshot version 的服务端授权 ContextPackage；权限、工具、Skill、MCP、计算能力、数据分类、Artifact 和预算均只能收窄。每个 child Run 固定计划 id/revision/task 血缘并使用独立 Run sandbox。Runtime Scheduler 通过持久 submission receipt、预算预留、task claim/lease 和 child submission receipt 承担重试去重，不能把 Workflow SDK step retry 或模型生成代码当成调度权威。完整契约、失败模式和框架边界见[Agent 委托与调度协议](Agent委托与调度协议.md)。

### 5.8 Workflow Runtime

工作流负责版本化、可复现的编排，而 Agent 负责在约束内进行非确定性推理。工作流节点通过类型化端口连接 Capability、Agent、条件、循环、并行、聚合和人工审批。

产品节点不是 Runtime Step 或供应商 API 的镜像。节点必须从真实创作任务、可理解的输入输出和可见成果出发，并区分定义节点、运行结果投影与 Runtime 原语；正式目录、优先级、准入模板和强制同步规则见[专业模式节点产品目录](专业模式节点产品目录.md)。新增或改变节点语义必须同步版本化 DSL、编译/运行适配、双语界面和验证，不能只在节点库或解释器中增加一个分支。

已发布工作流版本不可原地修改；一次运行绑定精确版本和输入快照。Agent 可以建议或生成工作流草稿，发布仍需验证。工作流可以调用 Agent，Agent 也可以调用已发布工作流，但双方运行记录必须保持独立且互相引用。

`CreativeCanvas` 是 Agent-first 创作空间；`ExecutionPlan` 是一个 AgentRun 的可恢复执行计划；`ProfessionalWorkspace` 是多个定义的编辑总览；`WorkflowDefinition` 是经过验证和版本化的可调用自动化；`WorkflowRun` 是某个定义版本的一次运行。它们不得共享一个含义模糊的“画布 JSON”。完整边界见[Agent-first 创作与工作流模型](Agent优先创作与工作流模型.md)。

Workflow SDK 是 WorkflowRun 的首个已验证执行适配器，不是视觉画布引擎。当前 `WorkflowDocument → WorkflowDefinition` 编译器已形成独立的 `0.3.0-draft` Schema：只保留输入输出、规范化节点配置、数据绑定、控制依赖和稳定执行序，剥离位置、标题、渲染器状态与运行生成结果；编译身份必须显式提供 workspace、definition 与 version，失败只返回诊断而不产生半成品。`WorkflowRuntimePort` 以 Muses 状态、错误、幂等键和 suspension id 定义启动、查询、取消、恢复与重试，不暴露 SDK Run、Hook token、stream 或 World 类型。首批节点解释器已证明该定义可以在 Postgres World 中按稳定顺序执行真实图像生成路径，以及显式 Harness 的 Start、服务端图像夹具、真实等待的 Selector、服务端 DesignDocument 夹具与 End；Selector 仅暴露 Muses suspension id，恢复前校验私有 Hook metadata 和候选白名单。领域解释状态、值存储与类型校验不依赖 SDK；当前仍未证明任意插件节点和正式通用 Job/Capability。AI Elements + XYFlow 可以投影 WorkflowDocument，但不能保存其权威 Schema。对应依赖方向、候选证据和验证顺序见[平台技术栈与 Agent Harness 路线](平台技术栈与AgentHarness路线.md)。

### 5.9 媒体能力模块

图像、视频、音频与音乐、文本、演示和未来媒体模块拥有各自的编辑语义与供应商适配器，共享 Asset、Capability、Job、Command、Revision 和 Provenance。

- 图像模块覆盖生成、编辑、蒙版、抠图、扩图、超分、OCR、视觉理解与格式处理。
- 视频模块覆盖生成、镜头、轨道、转码、代理文件、字幕、音频和时间轴渲染。
- 音频与音乐模块覆盖文生音乐、参考音乐、续写与变奏、配音、多语言语音、音效、环境声、分轨、人声处理、降噪、响度、母带、节拍/段落分析与时间轴混音；音频 Artifact 保留采样率、声道、时长、节拍、段落、轨道和许可语义，并可与镜头、角色、场景及品牌主题关联。
- 演示与商业材料模块覆盖页面、母版、布局、图表、演讲结构与可编辑导出。
- 品牌模块提供版本化品牌约束、批准资产、术语、受众与风格记忆，但不成为每个内核的隐式全局状态。

音频与音乐是跨媒体闭环的一等模块，不是视频的附属字段。平台不以自研音乐基础模型或复刻完整 DAW 为目标，而是通过能力与供应商适配器提供可编辑、可组合、可追溯的声音生产链路。音乐版权、模型条款、训练来源和商用许可必须进入 Provenance 与发布策略。

### 5.10 实时协作与策略

实时层传播临时 presence、游标、选择和已确认领域事件。并发模型按数据类型选择：文档文本或高频空间操作可以采用 CRDT/OT 或操作日志，工作流发布、计费、权限和外部发布必须使用服务端事务与显式冲突。

策略层统一处理身份、租户、角色、资源权限、能力权限、数据分类、地区限制、预算、审批和内容安全。授权必须在服务端命令或能力入口重新验证，不能信任客户端隐藏 UI。

## 6. 跨内核协议

### 标识与租户

持久对象使用不可变全局 ID，并显式携带 `workspaceId`。任何查询、事件、Job 和存储路径都必须保持租户边界；跨租户引用默认禁止。

### Schema 与兼容性

持久文档、命令、能力、事件与工作流都带 Schema 版本。新增可选字段应保持向后兼容；删除、重命名或语义改变需要迁移器和兼容窗口。读取旧版本时升级，写入时使用当前规范版本，并保留原始来源版本。

### 事件

领域事件描述已经发生的事实，采用 outbox 或等价机制与权威状态原子提交。消费者必须幂等；事件包含 `eventId`、`type`、`schemaVersion`、`workspaceId`、`aggregateId`、`revision`、`causationId`、`correlationId` 和时间戳。事件不是跨模块同步 RPC 的替代品。

### 错误

跨边界错误使用稳定机器码、用户安全信息、可重试标记和追踪 ID。供应商原始错误只能进入受控诊断，不直接泄漏给用户或上游契约。

### 可观测性

所有用户意图通过 `correlationId` 关联 AgentRun、WorkflowRun、Job、Command、模型调用、资产和发布记录。指标至少覆盖延迟、成功率、取消率、重试、供应商质量、Token/算力、资产处理量和单位成本。

Workflow SDK 的 Run、Step、Event、重试、时间和输入输出是耐久执行事实；AI SDK 与供应商响应提供 Token 和媒体用量；OpenTelemetry 负责跨进程 trace context；Muses UsageRecord、PriceBook 和积分账本负责业务计量。产品运行详情投影这些成熟来源，不另造一套调用链后端，也不在默认界面暴露原始内部 ID。

## 7. 数据与部署策略

当前阶段采用模块化单体 Web/API、独立 Worker、PostgreSQL、Valkey/BullMQ 与 S3 兼容对象存储。领域包不能依赖 Web 框架；供应商代码只能位于适配层；队列消息只传标识符和版本化小载荷，不传大型媒体。

建议的初始物理边界：

- Web：交互、画布壳、流式状态和服务端页面。
- API：权威命令、查询、策略、能力注册和运行控制。
- Worker：模型调用、媒体处理、工作流节点和异步提交。
- Realtime Gateway：达到多人协作里程碑时引入，可先由 Web/API 承担。

拆分新服务必须至少满足一项证据：需要独立扩缩容或硬件；需要独立故障/安全边界；部署节奏长期冲突；数据主权要求；团队所有权已经稳定。拆分后仍遵守同一领域契约。

## 8. 安全、合规与治理

- 所有对象查询和存储访问都以租户与资源授权为前置条件。
- OAuth、模型和发布供应商凭证使用服务端密钥管理，日志与事件禁止包含明文密钥。
- 上传内容进行类型、大小、恶意内容和安全策略检查；派生内容保留父级来源。
- 敏感素材进入模型前执行数据策略；模型供应商的数据保留与训练政策是路由输入。
- 外部发布、删除、付费生成和许可不明素材使用受策略控制的确认门。
- 审计日志与创作来源分离：前者服务安全责任，后者服务作品解释与版权证明。
- 数据导出、删除和保留必须覆盖数据库、对象存储、缓存、向量索引和供应商侧任务。
- 音乐、声音克隆和配音必须记录许可、说话人授权、模型条款和适用地域；未经授权的身份仿冒与声音克隆默认拒绝。

## 9. 开放架构与用户自由

完全开源和 Build in Public 是架构约束，而不只是仓库可见性：

- 核心领域模型、能力契约、持久格式、迁移器与官方实现应能由公开源码构建和验证。
- 云服务专有集成不得成为读取或导出用户项目的必要条件。
- 数据模型必须支持导出 Workspace 中用户有权访问的 Document、Asset、Revision、Workflow 与 Provenance；导出格式携带 Schema 版本和校验信息。
- 供应商适配层与自有凭证模式保持清晰边界，使社区能够新增或替换模型实现。
- 遥测默认最小化并可解释；公开指标只能来自经过隐私审查的聚合数据。
- 构建与发布流程必须扫描密钥、个人数据和第三方许可风险，公开开发不能扩大用户暴露面。
- 自托管与官方云共享核心契约；云端便利能力可以有独立实现，但不能破坏项目可迁移性。

具体开源许可证另行决策。架构不得在许可证确定前引入与候选许可证明显冲突的依赖或贡献条款。

## 10. 非功能目标

每个里程碑都应声明并测量对应 SLO，而不是沿用一组虚假永久数字。最低共同要求是：

- 自动保存不会静默丢失已确认操作；离线或断线后可明确恢复或报告冲突。
- Job 状态单调且可恢复，重复消息不产生重复收费或重复提交。
- 大型资产不经过应用进程中转；画布按视口和细节层级渲染。
- 每个外部调用有超时、取消语义、受限重试、熔断或降级策略。
- 所有跨租户访问、越权命令和未授权能力调用都有自动化负向测试。
- 核心操作支持键盘和可访问性语义；生成状态不能只通过颜色表达。

## 11. 演进规则

### 可以局部改变

框架、数据库访问库、渲染技术、模型供应商、队列实现、部署平台、UI 布局与单个能力算法，只要契约、迁移和质量门保持成立即可更换。

### 必须正式决策

- 改变长期 Goal 或产品主体。
- 合并或拆分核心内核职责。
- 改变权威数据所有者或跨租户模型。
- 允许 Agent 绕过 Command/Capability 边界。
- 改变兼容、来源、权限或工作流发布政策。
- 拆分关键服务且引入新的数据所有权。
- 改变完全开源、用户导出、自托管或 Build in Public 的核心政策。
- 确定或更换项目许可证、贡献者许可与商标治理政策。

### 禁止捷径

- 场景代码直接写其他内核数据库表。
- 把供应商响应当作稳定领域对象持久化。
- Agent 或工作流直接修改客户端画布状态后再“补记”服务端记录。
- 用扁平图片冒充结构化可编辑成果。
- 用无限重试掩盖非幂等执行。
- 在没有迁移器时改变持久文档 Schema。
- 让官方云成为读取、导出或迁移核心项目格式的唯一实现。
- 把用户私有项目、提示、素材或可识别遥测当作公开开发素材。

## 12. 价值门与验证策略

架构正确性通过契约测试、适配器测试、状态机属性测试、故障注入、迁移测试、租户隔离测试和跨入口组合测试共同证明。任何内核只有通过[内核验收路线](内核验收路线.md)定义的技术三层门，并改善[产品价值宪法](../shared/价值宪法.md)中的真实任务和指标，才能被标记为可复用且值得长期维护。

专业模式真实首图已经证明 DSL、Capability、Job、Asset、授权、费用和 Workflow SDK 耐久运行底座，但它不是默认设计体验，也不构成场景 MVP 准入。单 Agent 在创作模式中把自然语言需求转化为计划、真实图片、画布结果和 follow-up 修改的工程 Gate 已通过；当前边界转为指定 WorkflowDefinition 调用与完整可靠性 Gate。

单 Agent 必须先通过刷新/进程恢复、上下文压缩、幂等费用、预算、审批、取消、隔离、追踪和固定 eval；随后才增加 MusesAgent、领域 Agent 与 SubAgent 调度，再进入真实 MusesPPT。AI 短剧作为差异明显的第二场景验证跨图像、视频、对白、配音、音效和音乐的时间型生产。

## 13. 当前基础的映射

现有 OWorker SaaS 基础继续承担认证、账户、计费、PostgreSQL、Valkey、BullMQ、S3 兼容存储、审计、管理和 API/Worker 运行框架。它是平台基础，不是最终产品架构本身。

新增产品代码应逐步形成清晰包边界：`creative-canvas`、`professional-workspace`、`workflow-definition`、`professional-document`、`design-document`、`command`、`asset`、`provenance`、`job`、`capability`、`agent-core`、`agent-tools`、`agent-sandbox`、`workflow-runtime`、`image`、`video`、`audio` 与其他媒体能力。实际目录可以渐进形成，但依赖方向和权威所有权不得反转。
