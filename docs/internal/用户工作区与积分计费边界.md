# 用户工作区与积分计费边界

## 1. 当前决定

Studio 不是匿名模型演示页。进入 Studio、读取或修改工作流、上传素材、启动或查询运行、下载结果和恢复人工步骤都必须经过登录、邮箱验证、工作区成员关系和资源授权检查。

真实模型调用会产生不可逆外部费用，因此身份、所有权和积分计费是首图成果的一部分，不是商业化阶段再补的外围功能。

## 2. 身份与工作区

- Better Auth 继续拥有登录、邮箱验证、OAuth、会话和账户生命周期。
- 第一次进入 Studio 时为用户幂等配置一个个人工作区和 owner 成员关系。
- URL、请求体中的 `workspaceId` 只是资源定位信息，服务端必须通过当前会话重新验证成员关系。
- WorkflowDocument、WorkflowRun、Job、Asset、UsageRecord 和积分结算都显式携带工作区身份。
- 查询不匹配资源统一返回安全的 `404` 或授权错误，不能通过 ID 猜测跨工作区数据。

个人工作区是当前最小闭环，不把 `userId` 直接冒充长期 Workspace id。未来团队邀请、角色和企业工作区扩展成员关系，不改变资源所有权契约。

## 3. 积分账户与账本

每个工作区拥有一个积分账户。余额由不可变账本派生，不能通过覆盖单一余额字段作为唯一事实来源。

账本至少包含：

- `grant`：注册送积分、管理员调整或未来购买到账。
- `reserve`：付费运行开始前冻结预计最大积分。
- `settle`：运行完成后按实际用量和价格快照确认消费。
- `release`：失败、取消或实际费用低于预留时释放积分。
- `refund`：经审计的补偿，不删除历史消费。

每个条目包含工作区、账户、积分变化、原因、关联 WorkflowRun/Job、幂等键、操作者和时间。积分使用整数最小单位，避免浮点累计误差。

## 4. 付费运行事务

```text
验证会话与工作区
-> 编译并验证 WorkflowDefinition
-> 根据 modelRef、参数和 PriceBook 计算保守预计费用
-> 原子检查可用余额并创建 reservation
-> 启动 WorkflowRun
-> 记录供应商 usage 和输出
-> 按价格快照 settle，释放差额
-> 失败或取消时按“是否已产生供应商费用”结算或释放
```

同一个运行提交幂等键只能产生一个预留和一个 WorkflowRun。不能先调用付费供应商再检查余额；也不能因为 Workflow SDK 或 AI SDK 自动重试造成未知的重复收费。供应商返回不确定结果时保留 reservation 并进入人工可审计状态，不凭猜测自动退款。

## 5. 价格与实际用量

运行前显示预计积分或范围。运行后保存：

- 模型供应与版本。
- PriceBook 版本。
- 供应商请求标识（若提供）。
- AI SDK 标准 usage 与受控 provider metadata。
- 生成数量、实际尺寸、视频时长或其他媒体计量。
- 预计积分、预留积分、实际积分和释放积分。

Workflow SDK 负责耐久 Run/Step/Event 和输入输出事实；AI SDK/供应商返回模型用量；OpenTelemetry 关联跨服务 trace；Muses UsageRecord 和积分账本负责业务计量。任何一层都不重复发明其他层已经拥有的事实。

## 6. 与 Stripe 的边界

现有 Stripe 订阅与支付基础可以在商业策略确认后销售套餐或积分包，但本 Gate 不猜测商品、折扣、退款和企业合同。Stripe 成功事件未来只产生经过幂等验证的 `grant`；Stripe 记录不是模型消费账本，积分账本也不替代法币支付记录。

## 7. Gate 1.1 最小验收

- 未登录用户访问 `/studio` 被送往登录，并可在认证后返回。
- 未验证用户不能调用 Studio 付费 API。
- 登录用户获得稳定个人工作区，刷新后不变化。
- 不属于当前用户的工作区、Run 和 Asset 无法读取或修改。
- 新工作区获得可配置的开发期初始积分；发放只发生一次。
- 余额不足时模型调用之前失败，不产生供应商请求。
- 同一运行提交不重复预留；完成、失败和取消都有可审计结算结果。
- Studio 显示可用积分、预计积分和本次实际积分，技术账本 ID 默认不进入创作界面。

## 8. 当前实现证据

截至 2026-07-28，Gate 1.1 的身份、工作区和积分账本切片已经落地：

- `/studio` 由 Better Auth 会话和邮箱验证门保护；`/api/studio/context`、运行、恢复、取消、重试和资产下载都重新校验会话与工作区成员关系。
- 首次进入 Studio 在事务和 PostgreSQL advisory lock 内幂等建立个人工作区、owner 成员、积分账户和一次性初始 grant。Studio 本地状态与最近运行指针均按真实 `workspaceId` 隔离。
- `muses_workspace`、`muses_workspace_member`、`credit_account`、`credit_ledger_entry`、`credit_reservation` 和 `muses_workflow_run` 由 `0002_muses_identity_credits.sql` 创建；数据库触发器拒绝修改或删除已写入的账本条目。
- 真实付费节点在 Workflow SDK `start()` 和供应商调用前原子预留积分；余额不足返回 `402 insufficient-credits`。成功后按实际图片数结算并释放差额，明确失败释放预留，取消按已知用量结算，供应商结果不确定时保留预留并标记 `review_required`。
- Studio 顶栏显示可用积分，运行投影返回预计/实际积分与结算状态，账户计费页显示可用、预留积分和当前工作区。Stripe 付款与 Muses 模型消费仍保持独立账本。
- `tests/e2e/muses-studio.spec.ts` 以 10 条浏览器用例验证认证门、工作区/初始 grant 幂等、跨工作区拒绝、耐久恢复/取消/重试以及供应商调用前的余额不足拒绝。

## 9. 版本化定价当前状态

当前 `MUSES_INITIAL_CREDIT_MICROS=100000000`（初始 100 积分）仍是可配置的开发期 grant 策略，不是生产商业承诺。每图价格已停止读取 `MUSES_IMAGE_CREDIT_MICROS`，改为由 `price_book_entry` 的 `alpha-2026-07-28.1` 发布版本提供；当前两个 GPT Image 供应均为每张 1 积分的 Alpha 校验价，新价格必须发布新 PriceBook 版本。初版 `alpha-2026-07-28` 因 UTC 生效窗口错误已退役，修正通过追加版本完成，没有改写已发布价格事实。

Studio 估价、运行 Adapter 和管理员控制面已改为读取版本化 `model_offering`、`capability_profile` 和 `price_book_entry`。接下来的图生图、分辨率和新模型规格必须继续扩展 Profile/PriceBook，不得重新在节点或环境变量中创建第二价格事实源。
