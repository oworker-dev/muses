# 专业模式节点产品目录

## 1. 文档地位

本文是 Muses 专业模式节点的权威产品目录，回答四个问题：

1. 平台为什么需要某个节点。
2. 用户应如何理解和使用它。
3. 它在 DSL、运行时和界面中必须表达什么。
4. 它现在是否应该进入产品，而不是只在测试或未来设想中存在。

专业模式先行不代表 Muses 是 Coze、Dify 式 AI 应用开发平台。Muses 是具有工作流原生能力的 AI 设计平台；专业模式把创作生产线完整、无损地展示给高级用户，Coze 只作为节点配置、变量绑定、运行调试和画布操作的体验参考。

本文约束 `WorkflowDocument`、`WorkflowDefinition`、节点库、节点配置面板、运行结果、国际化文案、模板和测试。当前实现与本文冲突时，必须把差异记录为实现缺口，不能以现有代码反向修改产品理由。

## 2. 专业模式的统一用户心智

专业模式中的每条可执行链都必须能被用户理解为：

```text
我提供什么
→ AI、工具或人做什么
→ 我得到什么可见成果
→ 是否需要选择、编辑或继续处理
→ 最终交付什么
```

节点不是数据库表、SDK Step 或技术演示卡片。一个节点只有在用户能够回答以下问题时才具备产品意义：

- 它为哪项真实创作任务服务。
- 它需要什么输入，哪些值由每次运行提供，哪些是工作流固定配置。
- 它将产生什么可检查、可连接或可编辑的结果。
- 如何单独试运行或随整条工作流运行。
- 运行时发生了什么、耗时和成本是多少、失败后可以做什么。
- 用户得到结果后最自然的下一步是什么。

界面应通过节点名称、配置表单、输入绑定、结果预览和上下文续建入口直接表达这些答案。不能用教程弥补节点本身不可理解的问题。

## 3. 三层对象必须分开

| 对象 | 含义 | 是否进入发布定义 | 是否作为产品节点 |
| --- | --- | --- | --- |
| 定义节点 | 用户主动配置的输入、能力、控制、专业文档或输出步骤 | 是 | 是 |
| 成果与运行投影 | Asset、Job、候选图、进度、成本、错误和来源 | 否 | 通常不是；在节点结果区、结果面板或创作画布中展示 |
| Runtime 原语 | Workflow SDK workflow、step、Hook、sleep、stream、attempt 和 receipt | 否 | 否；只能实现节点语义 |

`image-result` 是当前 Gate 0 的结果投影，不是可发布的图像结果节点。Hook 是人工等待节点的实现手段，不是“Hook 节点”。Retry、timeout、cancel 和 parallel scheduling 默认是节点或运行策略，不因 SDK 提供这些原语就单独创造节点。

同一个产品节点可以由不同 Runtime 适配器实现。节点身份、输入输出和用户语义由 Muses DSL 定义，不能使用 Vercel Workflow SDK、BullMQ、模型供应商或画布库类型作为公共契约。

## 4. 节点优先级

| 等级 | 含义 | 准入要求 |
| --- | --- | --- |
| `P0` | 首张真实图片和 Gate 0 必需 | 当前阶段必须定义清楚并优先闭环 |
| `P1` | Platform Core Alpha 的通用图像创作闭环必需 | P0 可用后进入，必须证明跨入口复用 |
| `P2` | Agent Core 或首个真实场景需要 | 由真实 PPT、短剧、品牌或电商任务触发 |
| `P3` | 跨媒体、运营和生态扩展 | 只有价值证据和领域契约成熟后进入 |
| `待证` | 看似通用但尚无明确平台需求 | 不进入默认节点库，不提前实现 |

优先级表示产品验证顺序，不表示长期重要性。供应商模型不成为独立节点；例如 Seedream、GPT Image 或其他模型是“图像生成”节点的可替换能力配置，除非供应商能力具有无法由通用契约表达且已被用户验证的独特语义。

### 4.1 计划总表

| 阶段 | 要做的定义节点 | 首要结果 |
| --- | --- | --- |
| `P0` | `start`、`image.generate`、`end` | 用户能够生成并交付第一张真实图片 |
| `P1` | `asset.input`、`image.transform`、`human.review`、`document.design` | 图片能够引用真实素材、继续处理、人工把关和深度编辑 |
| `P2` | `flow.condition`、`flow.map`、`flow.collect`、`flow.subworkflow`、`text.generate`、`document.presentation`、`agent.run` | 形成可复用的复杂创作流程并验证 PPT 与 Agent 场景 |
| `P3` | 视频、语音/音频、音乐/音效、品牌、渠道适配、导出与发布节点族 | 完成短剧、短视频、品牌、电商和社媒跨媒体商业闭环 |

### 4.2 当前实现到目标节点的映射

| 当前 kind | 目标身份 | 当前结论 |
| --- | --- | --- |
| `start` | `start` | 单例和基础变量已验证；Asset 运行输入待补 |
| `image-generator` | `image.generate` | 默认路径已接真实图像适配器，支持单向变量/固定输入、参考图、模型驱动比例/分辨率/数量/质量和合法尺寸预览；完整 Job/UsageRecord 和通用集合基数仍待补 |
| `selector` | `human.review` | 等待/恢复技术语义已验证；正式审核契约和授权待补 |
| `design-document` | `document.design` | 最小编辑投影已存在；真实输入和权威持久化待补 |
| `end` | `end` | 默认首图模板已直接接收 Image；Harness 仍接收 DesignDocument，用户自定义多输出待补 |
| `image-result` | 无定义节点；属于 Asset/Job 结果投影 | 必须继续排除在发布定义之外 |

## 5. P0：首张真实图片闭环

### 5.1 开始 `start`

**用户心智**：定义“每次运行这条创作流程时，我要提供什么”。

**为什么平台需要**：可复用工作流必须把运行输入与固定配置分开。Prompt、参考素材、尺寸或渠道可以在每次运行变化，而模型策略和后续处理可以保持不变。Start 也是模板、API、Agent 和人工试运行共享的输入契约。

**目标契约**：

- 一个可发布定义恰好一个，不可删除或重复创建。
- 输入变量由用户命名并派生同名输出端口。
- P0 支持 `text`；首图闭环随后必须支持可选 `ImageAsset` 或 `ImageAsset[]` 参考输入，不能永远限制为 `text | number | boolean`。
- 每个变量明确类型、是否必填、默认值和面向用户的说明。
- 默认值属于工作流定义；试运行值属于本次 Run，不应改写定义。

**界面要求**：配置面板使用“运行输入”而不是内部 Schema 术语。试运行时只询问本次尚未提供的必填值。节点卡显示变量名称和类型，不显示 SDK 参数。

**当前状态**：已验证单例保护和 `text | number | boolean` 变量；Asset 类型运行输入尚未实现。

### 5.2 图像生成 `image.generate`

**用户心智**：让指定图像模型根据文字和参考素材生成一张或多张真实图片。

**为什么平台需要**：图像是 PPT、电商、品牌、社媒和短视频共同依赖的最小媒体能力，也是验证 Capability、Job、Asset、Provenance、成本和后续编辑连接的第一条真实链路。

**目标输入**：

- `prompt: text`，必填，可绑定变量或填写固定值。
- `referenceImages: ImageAsset[]`，可选。
- 后续按已验证能力增加 mask、control image 或结构参考；不得把供应商私有字段直接提升为通用端口。

**目标配置**：

- `modelRef`：能力和模型版本引用。
- `aspectRatio` 与 `1K | 2K | 4K` 快捷分辨率，或明确的自定义宽高。
- `count`：显式数量，默认 `1`，受模型与预算限制。
- 可选 seed、quality、style strength 等能力参数通过版本化配置表达。
- 运行前可见预计成本或成本范围，以及会生成的数量。

模型、比例、分辨率和参数选项必须来自已发布的 Model Offering 与 Capability Profile，不能硬编码在节点组件或节点联合类型中。模型的合法尺寸倍数、最小/最大像素和取整策略由 Profile/Adapter 解析；界面在运行前展示实际请求像素。模型不原生支持的 2K/4K 不能静默通过后处理伪装为原生能力。

**目标输出**：

- `images: ImageAsset[]`，即使数量为一也保留明确基数语义。
- Job、attempt、成本和 provenance 是运行投影，不作为普通数据流输出伪装成图片。

**界面要求**：输入数据源位于配置面板顶部。每个输入通过“变量绑定 / 固定值”选择唯一来源；绑定模式只读展示来源和值预览，并提供定位上游，不得编辑上游；固定值模式才显示当前节点自己的文字或素材编辑器。节点可单独运行。运行中显示排队、进度、取消入口和成本状态；完成后在节点结果区和结果面板直接显示真实缩略图与大图，不得只显示 `succeeded` 或 Asset id。结果可继续连接到选择、图像处理、设计画布或 End。

**当前状态**：Gate 1.1 已将节点模型字段迁移为版本化 `modelRef`。Prompt 与参考图各自只允许一个输入来源：变量模式只读绑定上游，固定模式只修改当前节点，不再由下游反向改写 Start。Studio 从已发布 Model Offering/Capability Profile 投影模型、比例、`1K/2K/4K`、自定义尺寸、数量和质量，运行前展示请求尺寸与 Adapter 实际尺寸；连续尺寸按模型约束合法化，离散模型只开放真实支持的组合。固定参考图通过工作区授权的 S3 预签名上传进入，服务端校验真实 MIME、字节数和尺寸，DSL 只保存稳定 Asset ID。运行前使用 PriceBook 原子预留积分，运行后按实际图片数结算。

当前 `image` 运行值以 `assetIds` 和可选 `assets` 数组表达一张或多张图片，仍是首图阶段的临时集合表示；Start 的 Asset 类型运行输入、供应商无关 Capability/Job 注册、正式 UsageRecord 和集合类型仍是后续真实任务暴露的缺口。生成结果保持供应商返回的真实像素和格式元数据，不以静默裁切伪装请求尺寸。当前 Studio 运行、参考/生成 Asset 和账本均执行工作区授权与提交幂等；固定三张 SVG、Selector 和 DesignDocument 只存在于 `?template=harness` 的确定性回归夹具，不能作为正式产品行为。

### 5.3 结束 `end`

**用户心智**：声明“这条工作流最终交付什么”。

**为什么平台需要**：模板、人工运行、Agent 调用和开放 API 都需要稳定、可命名、可验证的输出契约。End 不是装饰性终止符，也不应强迫所有工作流先进入设计画布。

**目标契约**：

- 一个可发布定义恰好一个，不可删除或重复创建。
- 由用户声明一个或多个命名输出，并派生输入端口。
- 输出至少可表达 `ImageAsset`、`ImageAsset[]` 和 `DesignDocumentRef`；后续扩展文本、视频、音频、演示和结构化数据。
- 所有必填输出必须由 Start 可达路径产生并完成类型校验。

**界面要求**：显示交付名称、类型和实际预览。整图运行完成后，结果面板首先展示 End 的业务成果，而不是 SDK return value。

**当前状态**：单例保护、可达性和类型校验已验证。默认模板的 End 直接接收并返回图像运行值，完成 `Start → image.generate → End`；显式 Harness 的 End 继续接收 `DesignDocumentRef`。用户自定义多个命名输出和更完整的集合基数仍待独立演进。

### 5.4 首图默认模板

正式专业模式的最小默认模板必须是：

```text
开始（prompt，referenceImages?）
→ 图像生成（count 默认 1）
→ 结束（image 或 images）
```

打开模板后，用户应在 60 秒内修改运行输入并获得第一张真实图片；从空白工作流开始，应在 3 分钟内搭建并运行同一链路。运行前用户可以预测模型、数量、比例和输出，运行后第一眼看到图片本身。

当前默认工作区已经是上述三节点模板。`Start → Image Generator → Selector → DesignDocument → End` 只通过 `/studio?template=harness` 提供，用于覆盖分支、人工等待和两层画布的 Gate 0 组合回归，不是默认产品工作流。

### 5.5 运行结果不是新节点

用户运行默认模板后，结果面板必须先回答“实际用了什么、得到了什么、花了多久和多少积分”，而不是展示 SDK 名称、Harness 说明、事件 JSON 或只有开发者能解释的状态。当前 `observability 0.1.0` 已把 Workflow SDK World 的 Run/Step 时序、Muses 节点事件、AI SDK usage 和不可变 PriceBook/reservation 快照组合为用户安全投影，并默认显示：

- 整次 Run 与节点的开始、完成和耗时；
- 图像节点实际收到的 Prompt 与参考图数量，以及输出数量；
- 公开 `modelRef`、Capability Profile 版本、请求/合法尺寸和 PriceBook 版本；
- 图片数量、供应商实际返回的 Token 用量、预计/实际积分和用户可读错误；
- 供应商不返回 Token 时明确显示“未返回”，不伪造为零。

这些事实属于 Run/Job/Asset 成果投影，不创建“运行详情”“Usage”或“Trace”节点。默认界面不暴露完整 Definition、供应商执行模型 ID、`creditContext`、对象字节、存储键、Hook token、原始堆栈、SDK Step 或 OpenTelemetry carrier。底层 attempt 只在次级诊断区显示；World 读取失败时降级为 Muses 事件摘要，不能把正常 Run 误报为不存在。

节点卡必须直接投影同一份运行事实：执行中使用高亮边框、明确的“运行中”状态和前端实时计时；完成、失败或取消后停止实时计时，并在节点下方保留结果摘要、固定耗时或用户可读错误。这里不建立第二套运行状态，卡片只消费 `observability`；整次 Run 结果面板继续承担模型、用量、计费和诊断详情。右侧工作区保持单一心智：未选择节点时显示全高 Agent 面板，选择节点后在同一位置切换为节点配置，取消选择即返回 Agent。

## 6. P1：平台核心图像创作闭环

### 6.1 素材输入 `asset.input`

**用户心智**：把已有图片或文件作为可复用的创作输入。

**为什么平台需要**：真实设计任务很少只有文字。品牌素材、客户原图、产品图和历史结果必须可以进入工作流并保留来源，而不是被临时上传控件隐藏。

**目标语义**：引用工作流中固定的已上传或已有 Asset，可输出单个或多个类型化 Asset；上传、权限和版本由 Asset 边界负责，不执行模型任务。每次运行由调用者临时提供的素材属于 Start 的 Asset 变量，固定项目素材属于 `asset.input`，两者不能混成同一隐式上传状态。

### 6.2 图像处理 `image.transform`

**用户心智**：对已有图片执行明确、可预期的修改。

**为什么平台需要**：平台价值不能停在一次性生成。电商、PPT、品牌和社媒都依赖局部修改、尺寸适配和质量提升。

**首批能力范围**：先通过一个版本化通用契约验证真实适配器，再按用户任务拆分易理解的预设动作。候选包括重绘/扩图、背景移除或替换、放大增强、裁切与尺寸适配；不为供应商的每个 API 方法创建节点。

**目标输出**：新的 `ImageAsset` 或 `ImageAsset[]`，保留父 Asset、参数、模型和 Job provenance；处理不得原地覆盖已确认资产。

### 6.3 人工选择 `human.review`

**用户心智**：运行到这里暂停，让我或指定成员从候选中确认继续使用的结果。

**为什么平台需要**：高质量商业创作需要可控委托和人工把关，尤其涉及品牌、成本、发布和客户审稿时。它证明长任务能够安全等待并恢复。

**目标契约**：输入候选 Asset 集合，配置选择数量、审核人、超时和超时策略，输出已确认 Asset 或 Asset 集合。只有用户主动添加或模板明确需要审核时才存在；图像数量大于一不自动创建该节点。

**界面要求**：直接显示候选媒体、选择规则和剩余时间；恢复操作使用 Muses suspension id。Hook token 和 SDK Hook 永不进入客户端或节点 DSL。

**当前状态**：当前 `selector` 的单人单选、Hook 等待、超时、恢复和取消已通过 Harness 验证；通用候选集合、审核策略和正式授权仍待实现。

### 6.4 设计画布 `document.design`

**用户心智**：把输入素材放入一个持续可编辑的视觉文档，继续处理图层、文字、形状和布局。

**为什么平台需要**：Muses 必须把生成结果转化为结构化、可继续修改的作品，不能只交付孤立图片。DesignDocument 也是未来演示、品牌物料和社媒设计的专业编辑基础。

**目标契约**：输入可选 Asset 和现有 `DesignDocumentRef`，输出新修订的 `DesignDocumentRef` 及显式发布的 Asset/选择集。外层节点只引用文档和预览，不复制内部图层。

**界面要求**：节点显示真实预览和修订；进入后聚焦专业编辑器，退出时恢复外层视口和选择。它是可选后续步骤，不是每次生成图片的必经节点。

**当前状态**：已有最小 Konva 编辑和引用 Harness；服务端权威持久化、完整修订和真实图片输入仍待完成。

## 7. P2：复用、控制与首个场景节点

这些节点只有在 P0/P1 闭环成立后进入，不能为了让节点库看起来丰富而提前实现。

| 节点 | 用户任务与平台理由 | 约束 |
| --- | --- | --- |
| 条件分支 `flow.condition` | 根据审核、品牌规则、渠道或内容属性选择后续路径 | 条件必须类型化且可解释；不能执行任意不受控代码 |
| 批量映射 `flow.map` | 对页面、镜头、产品、尺寸或渠道列表重复执行同一子流程 | 必须有并发、数量、预算和失败策略；不允许无界循环 |
| 聚合 `flow.collect` | 汇总并行生成的页面、镜头或素材结果 | 保留顺序、缺失项和部分失败语义 |
| 子工作流 `flow.subworkflow` | 把验证过的创作步骤版本化复用 | 引用不可变发布版本并显式映射输入输出 |
| 文本生成/处理 `text.generate` | 支撑 Brief 梳理、PPT 文案、脚本、标题和社媒文案 | 结果必须可编辑、可追溯；不与 Agent 节点混为一谈 |
| 演示文档 `document.presentation` | 承载 MusesPPT 的页面、母版、组件和可编辑交付 | 由场景阶段定义，不能由当前 DesignDocument 或 PPTX 实现反推契约 |
| Agent `agent.run` | 在受控工具、预算和权限下完成非确定性创作任务 | 只在 Agent Core 通过后进入；不得拥有画布或数据库写旁路 |

并行执行通常由无依赖图结构自然产生，不单独创建“并行节点”。重试、取消、超时和错误分类默认属于节点运行策略；只有真实用户任务需要显式错误分支时，才评估错误处理节点。

## 8. P3：跨媒体与商业闭环节点

| 节点族 | 计划节点 | 服务的平台需求 |
| --- | --- | --- |
| 视频 | `video.generate`、`video.transform`、`document.video` | AI 短剧、短视频、广告素材、镜头与时间线编辑 |
| 语音与音频 | `speech.synthesize`、`audio.transform`、`document.audio` | 旁白、对白、音频清理、轨道与混音 |
| 音乐与音效 | `music.generate`、`sound.generate` | 短剧、视频、演示和品牌内容的完整声音闭环 |
| 品牌 | `brand.context`、品牌检查能力 | 跨图像、视频、PPT 和社媒保持视觉与语言一致性 |
| 渠道适配 | 尺寸/格式/文案变体能力 | 电商、社媒和广告的批量多渠道交付 |
| 导出与发布 | `deliver.export`、`publish.channel` | 从结构化作品到文件或渠道的最终商业交付 |

导出和渠道发布具有外部副作用，必须在节点上明确目标、权限、覆盖范围和确认策略。发布不能因为工作流重试而重复发生；默认需要幂等键、审计和高影响确认。

## 9. 明确不因对标平台直接新增的节点

下列 Coze/Dify 常见节点不自动进入 Muses：HTTP 请求、数据库 CRUD、会话管理、任意代码、JSON 序列化、知识库查询和通用插件调用。只有当真实创作任务无法由 Capability、Agent 工具、集成适配器或子工作流清晰表达，并有跨场景复用证据时，才按准入流程评估。

节点库不是底层 SDK 能力清单。Muses 的竞争力来自连续创作、可见成果、专业编辑、可控委托和开放资产，而不是复刻通用自动化平台的节点数量。

## 10. 节点准入模板

新增定义节点前，提案必须同时写清：

1. **真实任务**：至少一个目标用户要完成的创作任务，不能只写“技术上通用”。
2. **不可替代性**：为什么现有节点、配置、Agent 工具或子工作流不能清晰完成。
3. **用户心智**：一句不含 SDK、数据库或 Schema 术语的说明。
4. **类型契约**：稳定 kind、版本、输入输出、集合基数、必填项和兼容规则。
5. **配置边界**：定义期配置、运行期输入、密钥和服务端策略分别属于哪里。
6. **执行语义**：纯转换、Capability、人工等待、专业文档、Agent 或外部副作用。
7. **结果体验**：节点卡、配置面板、运行中、成功、失败、空结果和后续动作如何呈现。
8. **可靠性**：幂等、重试、取消、超时、部分失败、恢复、成本和副作用策略。
9. **来源与权限**：输入和输出的 provenance、租户授权、审核与审计要求。
10. **双投影**：专业模式完整表达，以及创作模式将来如何隐藏、折叠或呈现。
11. **验证证据**：领域测试、编译/发布测试、Runtime 测试、浏览器任务测试和国际化检查。
12. **退出策略**：节点被替换、弃用或迁移时，已发布定义如何继续运行。

缺少其中任一项的节点只能进入实验 Harness，不能进入正式节点库或公共 DSL。

## 11. 节点实现完成定义

一个节点不能因为“能拖到画布上”或“后端 switch 已支持”就标记完成。至少满足：

- 目录中存在已批准的产品理由和阶段。
- 领域 Schema、端口类型、集合基数、配置 Schema 和迁移策略明确。
- `WorkflowDocument → WorkflowDefinition` 编译、校验和版本身份成立。
- Runtime adapter 不泄漏 SDK 类型，输入输出可序列化并支持重放。
- Capability/Job/Asset/Provenance 或文档修订边界按节点类型成立。
- 节点卡和配置面板让用户读懂输入、行为、结果、成本和下一步。
- 单节点试运行与整图运行的输入来源和结果一致。
- 空、等待、运行、成功、失败、取消、超时和重试状态有明确体验。
- 中英文文案同步，不把开发 Harness 文案作为产品文案。
- 领域、编译、Runtime 和 Playwright 核心任务测试通过。

## 12. 强制同步规则

任何新增、重命名、拆分、合并、弃用或改变输入输出语义的节点，必须在同一个变更中同步：

1. 本文的目录、优先级、产品理由、状态和契约摘要。
2. `WorkflowDocument` 与 `WorkflowDefinition` 的版本化 Schema、迁移和兼容性说明。
3. 编译器、发布校验、解释器/Capability adapter 和运行事件投影。
4. 节点库、节点卡、配置面板、运行结果和上下文续建规则。
5. `zh-CN` 与 `en` 国际化文案。
6. 领域测试、编译/发布测试、Runtime 测试和至少一条用户任务 E2E。
7. 相关模板、接口文档、交付证据和 APCC 任务/决策。

如果变更只修改其中一部分，节点不得宣称完成。代码评审必须检查本文；自动一致性检查应在节点种类稳定后由 Schema 生成或注册表驱动，减少手工清单漂移。

## 13. 当前实现差距与最近顺序

当前代码已跑通默认 `start → image-generator → end` 的真实首图工程闭环，并提供面向用户的真实输入、输出、耗时、模型/Profile/PriceBook、用量和积分观测；`image-result` 继续只作为本地 Harness 成果投影并从发布定义排除。五节点 Selector/DesignDocument 链只证明 Gate 0 耐久等待与两层画布组合，不定义真实生图产品。

最近顺序固定为：

1. 由产品负责人无讲解完成默认三节点真实生图，记录首图时间、停顿、误解和结果后续动作。
2. 只修复该用户验收暴露的阻断；当前已知但未阻断首图检查的缺口包括运行请求幂等、租户授权、真实成本和执行中取消供应商请求。
3. Gate 1 通过后，以一个真实 PPT 任务判断优先补参考素材、图像处理、显式 `human.review` 还是可选 `document.design`。
4. 只有真实任务证明需要，才把当前临时图像集合表示升级为通用 Asset 集合与 Capability/Job 契约。
5. P0/P1 通过后，再依据 Agent 和场景证据新增 P2/P3 节点。

后续实施状态以 APCC 为准；本文负责说明为什么做这些节点以及它们必须为用户带来什么结果。
