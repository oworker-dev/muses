# 用户成果驱动交付计划

## 1. 当前唯一工程目标

Gate 1 的真实图像工程闭环已经形成，产品负责人无讲解验收继续并行记录。自 APCC 决策 `agent-first` 起，当前唯一工程价值点是：

> 让目标用户在不理解工作流的情况下表达创作需求，由单 Agent 建立计划、生成真实图片、把结果组织到 CreativeCanvas，并可通过自然语言继续修改。

既有专业画布、首图 Capability 和耐久运行证据全部保留为专业模式与 Agent 工具底座。`CreativeCanvas`、`ExecutionPlan` 和 `WorkflowDefinition` 使用不同根对象，完整边界以[Agent-first 创作与工作流模型](Agent优先创作与工作流模型.md)为准。

本计划最初落实 APCC 决策 `decision-5`，当前顺序由 `agent-first` 决策修订。节点产品语义以[专业模式节点产品目录](专业模式节点产品目录.md)为准，架构所有权仍以[长期架构](长期架构.md)为准。

## 2. 不变边界与本次纠偏

### 继续坚持

- 专业模式保留完整工作流 DSL，创作模式使用独立 CreativeCanvas 并共享底层 Command、Capability、Asset、Variable 和 Provenance。
- Muses 是 AI 设计平台，不是 Coze/Dify 式 AI 应用开发平台。
- `CreativeCanvas`、`ExecutionPlan`、`ProfessionalWorkspace`、`WorkflowDefinition` 与 `WorkflowRun` 分开。
- 用户成果、Asset、Job 和运行投影不冒充定义节点。
- UI、Agent、工作流和开放 API 最终通过同一 Query、Command 与 Capability 边界行动。
- 权限、幂等、防重复计费、来源和用户数据安全不能为了更快演示而绕过。
- Studio 与全部 Studio API 必须登录、验证邮箱并通过工作区授权；匿名使用真实生产模型不是可接受的开发默认值。

### 立即停止

- 不再按“画布完成 → 文档完成 → Asset 完成 → Job 完成 → 能力完成”的组件顺序串行开发。
- 不再因为 Workflow SDK、画布库或供应商 API 提供某个原语就创建产品节点。
- 不再把固定三结果、人工 Selector、DesignDocument 和耐久 Harness 强制塞进每次生图。
- 不在单 Agent 可靠前补齐完整设计编辑器、多供应商路由或复杂多 Agent 拓扑。
- 不用测试数量、代码量、节点数量或 APCC 百分比代替用户获得感。

## 3. 固定工作循环

每个价值 Gate 都使用同一个循环：

```text
定义用户要得到的成果和最小护栏
→ 用当前产品完整执行一次，不先改代码
→ 记录阻断、困惑、错误预期和不可见结果
→ 只选择最影响成果的一个缺口
→ 交付最小纵向修复
→ 让同一用户重跑同一任务
→ 通过、继续补缺口、删除复杂度或停止
```

规则：

1. **先观察再实现**：除已知安全硬门外，新增实现任务必须引用一次用户路径观察或真实场景证据。
2. **一次补一个主要缺口**：每个切片必须从用户动作贯穿到真实结果，不同时扩张多个内核。
3. **结果通过后再抽象**：先让一个入口工作，再验证第二入口；没有复用证据不升级为通用内核。
4. **失败回到具体缺口**：不通过时记录用户卡在哪里，不以“继续完善架构”作为默认回答。
5. **无关能力不顺手开发**：修改相邻模块时不能顺带实现尚未进入当前成果的节点或框架。
6. **护栏不后补**：权限、秘密、幂等、重复计费和资产所有权是成果的一部分，不属于发布前清单。

## 4. Gate 1：用户友好的真实生图闭环

### 4.1 标准任务

第一条正式产品模板只有：

```text
Start（本次 Prompt，可选参考图）
→ image.generate（真实模型，count 默认 1）
→ End（ImageAsset 或 ImageAsset[]）
```

产品负责人依次执行两条路径：

1. **模板路径**：打开“生成一张图片”模板，修改运行输入并生成结果。
2. **空白路径**：从只有受保护 Start/End 的空白工作流添加并连接 `image.generate`，完成配置和运行。

固定三候选 + `human.review` + `document.design` 继续作为组合 Harness。它不进入首图默认模板，只有用户主动需要多结果审核或深度编辑时才添加。

### 4.2 用户在运行前必须看懂

- Start 表示“这次运行我要提供什么”，而不是隐藏 Prompt 的技术输入节点。
- 图像生成节点会调用哪个模型、使用什么 Prompt、比例和数量。
- `count` 默认 1；用户没有设置多个结果时，系统不能擅自生成三个方向。
- Prompt 是本次运行输入还是固定工作流配置，两者不能混淆。
- 输入绑定是单向的；下游节点不能通过自己的编辑器改写上游变量。
- 模型可用的文生图/图生图、比例、1K/2K/4K、自定义尺寸和模型合法化后的实际像素。
- 预计成本或可理解的成本范围，以及运行会产生什么类型的输出。
- End 表示最终交付图片，不强制要求先进入 DesignDocument。

### 4.3 用户在运行中和运行后必须得到

- 点击运行后立即得到明确反馈，不怀疑按钮是否生效。
- 可见排队、生成、完成、失败和取消状态；技术细节默认折叠。
- 完成后第一视觉结果是真实图片，不是 run id、Asset id、事件列表或 `succeeded` 标签。
- 可以打开大图检查，并至少完成下载或继续连接下一步骤中的一种真实使用动作。
- 图片保留 Prompt、模型、尺寸、时间、成本和来源，但这些信息不遮挡结果。
- 刷新后已确认结果仍属于当前工作区；失败不会出现重复资产或重复计费。
- 错误信息说明发生了什么、是否产生费用、已有状态是否安全以及现在能做什么。

### 4.4 成果指标

| 指标 | Gate 目标 | 记录方式 |
| --- | --- | --- |
| 模板路径首图时间 | 无讲解 `≤ 60 秒`，不含模型实际排队时间 | 从页面可交互到 Job 提交；模型耗时单独记录 |
| 空白路径首图时间 | 无讲解 `≤ 3 分钟`，不含模型实际排队时间 | 从空白工作流到 Job 提交 |
| 关键节点理解 | 用户能用自己的话说明 Start、生成和 End 的作用 | 操作后简短复述，不提示术语 |
| 运行前预测 | 用户能预测模型、比例、数量和最终输出 | 提交前记录答案 |
| 结果发现 | 完成后无需寻找即可打开真实大图 | 记录首次看到并打开结果的时间 |
| 阻断性错误 | `0` 个无法自行恢复的产品阻断 | 观察日志和任务记录 |
| 资产连续性 | 刷新后结果仍可检查和继续使用 | 同一工作区刷新验证 |
| 重复副作用 | 同一幂等提交不重复调用、计费或创建结果 | 服务端与资产记录验证 |

时间预算用于发现摩擦，不鼓励用隐藏行为制造表面速度。真实模型等待时间、网络时间和用户配置时间分开记录。

### 4.5 Gate 通过条件

以下条件必须同时成立：

- 使用一个真实、可替换的图像生成适配器，不再用确定性 SVG 冒充产品结果。
- 模板路径和空白路径均能完成，用户不需要理解 Harness、Hook、Schema 或 Workflow SDK。
- 用户能在运行前正确预测行为，在运行后立即找到并检查图片。
- 已确认 Asset、工作区所有权、幂等和成本边界成立。
- 余额在供应商调用前检查并预留，运行完成、失败或取消后产生可审计结算；匿名或越权请求不消耗平台凭证。
- 中英文界面表达同一产品语义。
- 产品负责人完成一次无讲解验收并明确决定通过。

自动化和开发者自测只能证明回归，不代替产品负责人实际操作。

## 5. 缺口如何进入开发

首图审计按以下顺序记录问题：

| 缺口级别 | 判断 | 处理 |
| --- | --- | --- |
| `G0 成果阻断` | 无法提交真实 Job、看不到图片或无法继续使用 | 当前切片立即修复 |
| `G1 心智阻断` | 不知道节点做什么、输入从哪里来、会生成几张或为什么需要下一节点 | 当前 Gate 内修复 |
| `G2 连续性阻断` | 刷新丢失、结果不属于工作区、失败不可恢复或重复收费 | 当前 Gate 内修复 |
| `G3 明显摩擦` | 可以完成但停顿、误点、结果难检查或高级信息干扰 | 影响验收指标时修复 |
| `G4 扩展需求` | 多结果审核、深度编辑、图像处理、多模型、批量或 Agent | Gate 通过后由真实场景决定 |

已知缺口只是待验证假设：

- 当前默认图错误地强制三结果、Selector 和 DesignDocument。
- Start 只有基础标量变量，尚不能自然表达每次运行的参考图。
- `image-generator` 没有真实 Capability、用户可配置数量和明确集合输出。
- End 当前只接受 DesignDocument，不能直接交付图片。
- 运行结果仍混有 Harness 与 SDK 心智，真实媒体不够突出。
- Asset/Job/工作区所有权尚未形成正式产品闭环。

审计可以确认、拆分、降级或删除这些假设。只有确认后的缺口进入实现；不得因为它已经写在本文就跳过实际用户路径。

## 6. Gate 1 实施顺序

### Step 0：冻结验收，不写产品代码

- 固定两条用户任务、观察方法、指标和硬护栏。
- 选择可安全使用的真实图片 Prompt 与参考素材，不把私有客户材料写入仓库。
- 确认当前可用图像供应商凭证和开发成本上限；只选一个适配器，不做供应商矩阵。

### Step 1：按当前产品走查并形成缺口表

- 从全新本地状态打开 `/studio`。
- 分别尝试模板和空白路径，全程不借助代码或开发者解释。
- 对每个停顿记录：用户目标、实际看到的内容、预期行为、严重度和最小修复。
- 产出按 `G0 → G4` 排序的短缺口表；没有证据的技术任务不进入下一步。

### Step 2：交付最小首图纵向切片

当前已知最小候选范围是：

1. 修正首图 DSL 基数、Start 运行输入、End 图片输出和默认模板。
2. 接入一个真实图像生成 Capability，形成最小 Job 与 Asset 权威记录。
3. 让节点配置、运行输入和结果面板以图片成果为中心。
4. 只补工作区授权、幂等、防重复计费、刷新连续性和错误恢复所需的基础设施。

这四项必须作为一条可运行切片交付，不能先分别宣布“内核完成”。审计若证明某项并不阻断 Gate，应从当前切片移除或缩小。

### Step 3：产品负责人实操验收

- 清空本地状态后重新执行两条路径。
- 记录指标、困惑和实际结果，不在操作过程中即时解释。
- 任一硬门失败，创建指向具体观察证据的缺口任务并重跑。
- 全部通过后，由产品负责人记录 Gate 通过决定。

## 7. Gate 2：单 Agent 驱动创作空间

当前先完成框架无关 Agent Core、Operation Gateway、Skill/MCP/沙盒边界和 Harness 对照，再执行以下用户链路：

```text
提出创作需求
→ Agent 检查画布、资产、模型和预算
→ 必要时澄清并展示计划
→ 创建/配置/运行图像步骤
→ 将真实结果放回 CreativeCanvas
→ 用户 steer 修改比例、内容或方向
→ Agent 局部修订并继续运行
```

Gate 必须同时证明刷新和 Worker 重启恢复、上下文压缩不漂移、幂等费用、预算停止、审批、取消、Workspace 隔离、追踪和固定 eval。Agent 不得通过 DOM、`localStorage` 或数据库旁路写画布。

截至 2026-07-29，Gate 2 已通过两个连续工程切片：自然语言输入触发两次模型调用和一次 `image.generate`，真实 Asset 通过 Operation Gateway 写入 `CreativeCanvas.items`；Studio 默认进入创作模式，Asset 作为可移动对象投影到画布，拖动位置和结果在刷新后恢复；AgentRun 持久化三步最小 ExecutionPlan，面板可展开计划、依赖、状态和结果证据。桌面与移动端均显示非空真实图片且无页面溢出。

生成图片的产品权威记录现由 Muses PostgreSQL 与对象存储共同承担，Workflow SDK Postgres World 只承担耐久执行事件和运行投影。图片读取不再依赖 SDK `returnValue`，避免执行 World 生命周期反向决定用户 Asset 生命周期。当前未通过项已收敛为 steering/follow-up 的真实用户链路，以及 Gate 2 要求的重启、压缩、费用、预算、审批、取消、隔离、追踪和固定 eval；不得把这次画布投影描述成完整创作体验已经完成。

steering 首次真实探针已经验证失败安全性：空闲期预算缺陷在任何模型或计费副作用前暴露并已修复；重试到达模型层后又被外部供应商余额阻断，仍未创建图像 Job、扣减 Muses 积分或修改 Canvas。供应商异常现统一映射为稳定产品错误，Web API 对历史 Run/Event 同样脱敏；再次受控重试确认失败信息不再暴露供应商余额和 request id，且所有 Muses 副作用仍为零。新增结果的非重叠比较布局已通过单元测试，但必须等真实供应商调用恢复后用同一路径验证，不能以布局测试替代用户成果。

## 8. Gate 3：最小 Agent Orchestration

单 Agent 可靠后，增加 MusesAgent、版本化 Domain Agent Profile、受限 SubAgent 和 Runtime Scheduler。简单任务仍允许单 Agent 或直接 Capability 完成，固定组织层级不写入内核。

## 9. Gate 4：用真实 PPT 场景扩展能力边界

Agent Core 可靠性 Gate 和最小 Orchestration 通过后，选择一个可脱敏真实 PPT 定制任务。每次只补当前任务的第一个成果阻断；文本、研究、PresentationDocument、模板、布局、图表、设计画布、PPTX 和可编辑重建都仍是候选，不一次性立项。

### 9.1 PPT Gate 结果

- 至少一个真实 PPT 任务取得可检查、可编辑的阶段成果或完整交付。
- 每个新增节点和内核都有对应用户阻断、前后对比和复用判断。
- 场景特例留在 Presentation/PPT 能力，不进入通用工作流、Asset、Job 或 Agent 内核。
- 未改善任务结果的新增复杂度被删除、降级或停止。

PPT 之后再用 AI 短剧等差异明显场景验证跨媒体复用，并只扩展视频、语音、音效、音乐和时间线中真实缺失的部分。

## 10. 技术计划的新角色

现有技术计划不删除，改为缺口池：

| 计划 | 何时拉取 |
| --- | --- |
| 工作流画布 Alpha | 用户在首图或 PPT 中遇到定位、连接、拖动、保存或历史阻断 |
| DesignDocument Alpha | 用户需要把结果继续做成可编辑设计，或 PPT 页面编辑验证需要 |
| Asset/Job/Capability Alpha | 真实模型调用、结果连续性、成本、权限或来源暴露缺口 |
| Workflow Runtime | 真实任务需要长时间等待、人工恢复、取消或可靠重试时 |
| Agent Core | 当前主 Gate；已有真实图像 Capability 是首个工具闭环 |
| Agent Orchestration | 单 Agent 通过可靠性 Gate 后进入 |

被拉取的技术任务只完成当前成果所需范围。完成后回到用户任务重跑，不继续沿模块内部路线自然扩张。

## 11. 证据与停止规则

每次 Gate 至少保留：

- 任务版本、环境、用户角色和隐私边界。
- 运行前预期、操作记录、结果、耗时和成本。
- 按严重度排序的缺口与对应修复。
- 修复前后同一任务的对比。
- 通过、继续、删除、降级或停止决定。

禁止将用户私有材料、供应商密钥或客户身份写入公开仓库。可以保存脱敏任务描述、公开测试素材、聚合指标和不含秘密的运行证据。

出现以下情况时停止当前扩展：

- 用户成果已经通过，新增工作不再改善当前 Gate。
- 连续两个切片只增加内部完整度，没有改变用户任务结果。
- 新抽象只有一个调用方，且没有明确第二入口验证计划。
- 为支持未来场景而显著增加当前心智或维护成本。
- 真实证据推翻了节点理由、默认值或当前技术假设。

停止不等于放弃长期能力；它意味着能力回到缺口池，等待真实任务再次拉取。

## 12. 当前 APCC 顺序

当前主线是：

1. A0-A2：Agent-first 产品对象、工作流调用身份、Node Type Registry 和 AgentRuntimePort。
2. A3：服务端权威 Operation Gateway。
3. A4-A6：独立 Agent Core、Skill/MCP/沙盒和 Harness 对照。
4. A7：最小 Agent 生图闭环、CreativeCanvas 可视投影、可移动 Asset 和持久最小计划已验证；继续交付 steering/follow-up 用户链路。
5. A8-A9：指定工作流调用与可靠性 Gate。
6. A10：最小 Agent Orchestration。
7. A11：PPT，然后 AI 短剧。

实时任务、负责人和状态以 `apcc status` 为准；本文负责保持交付原则、Gate 和证据方法长期一致。
